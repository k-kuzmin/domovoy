# 0010. Любой недоступный внешний компонент делает сервис Unhealthy

**Статус:** принято, пересматривается на этапе 2

## Решение

Агрегация состояния в `/health`:

| Состояние компонента | Вклад в общий статус |
|---|---|
| `ok` | `healthy` |
| `not_configured` | `degraded` |
| `unreachable`, `rejected_by_geography`, `error` | `unhealthy` |

Различия между компонентами нет: недоступная база и недоступный
провайдер LLM дают одинаковый результат.

## Почему так

Напрашивается более тонкое правило: недоступный провайдер LLM — это
`degraded`, потому что ТЗ предусматривает режим «только быстрый роутер»
(NFR-COST-2), в котором система остаётся полезной без модели.

Правило верное, но опирается на функциональность, которой пока нет:
быстрый роутер появится на этапе 1, режим деградации — на этапе 2. Пока
их нет, «LLM недоступна, но система работает» — неправда, и различать
эти случаи означало бы описывать в коде поведение, которого не
существует.

## Следствия

- При настроенном, но недоступном Home Assistant `/health` отдаёт 503.
  На автозапуск это не влияет: `docker compose` не перезапускает
  контейнер по результату healthcheck, а `restart: unless-stopped`
  реагирует только на завершение процесса.
- Пересмотреть вместе с реализацией NFR-COST-2: тогда у провайдера LLM
  появится основание отдавать `degraded`, а у базы и Home Assistant —
  остаться критичными.
