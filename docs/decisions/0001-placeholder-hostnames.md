# 0001. В репозитории только плейсхолдеры вместо реальных хостов

**Статус:** принято
**Расходится с:** раздел 0 ТЗ

## Противоречие

Раздел 0 ТЗ фиксирует домен проекта и поддомены для Backend и push как
часть идентификации. Раздел 5.1.3 того же ТЗ запрещает «имена хостов и
поддоменов» в репозитории. Оба требования одновременно выполнить нельзя.

## Решение

Приоритет у запрета. В репозитории — только `api.example.com`,
`push.example.com` и имена сервисов Docker. Реальные имена живут в `.env`
на целевой машине, а он закрыт `.gitignore`.

## Почему так

Поддомен Backend — это адрес входа в домашнюю сеть. ТЗ само отмечает,
что публичный домен индексируется и сканируется (AR-1.2), и требует
дополнительного рубежа на стороне Cloudflare именно потому, что
приложение не должно быть единственной защитой. Публиковать адрес входа
в README портфолио — добавлять сканирующим работы бесплатно, ничего не
получая взамен: читателю портфолио имя хоста ничего не объясняет.

## Следствия

- README, `.example`-файлы и `docker-compose.yml` содержат плейсхолдеры.
- Запрет проверяется правилом `domovoy-real-hostname` в `.gitleaks.toml`,
  а не памятью разработчика: правило ловит домен проекта в любом файле.
- Скриншоты и записи экрана перед публикацией проверяются отдельно
  (REPO-6) — их содержимое gitleaks не читает.
