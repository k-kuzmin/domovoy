# 0019. Таблица сигналов риск-скора лежит в JSON, а не в `pipeline/risk.yaml`

**Статус:** принято

## Решение

Конфигурация риск-скора — `pipeline/risk.json`. ТЗ советника (фаза 2) называет
файл `pipeline/risk.yaml`; расположение и роль сохранены, формат изменён.

Читает конфиг `scripts/risk-score.sh` через `jq`. Никакого второго формата и
никакого преобразования между ними нет: файл один.

## Почему не YAML

Разбирать YAML в обвязке нечем.

- **`yq` — новая внешняя зависимость.** Набор зависимостей проекта закрыт, и
  любая добавка требует обоснования до установки. Обоснование «иначе конфиг не
  в том формате, который назван в ТЗ» — это плата инструментом за букву, а не
  за возможность.
- **Свой разбор подмножества YAML на `sed` и `awk`** противоречит правилу «не
  изобретать своё» из `.claude/CLAUDE.md`. Собственный парсер ошибается молча,
  и цену ошибки платит файл, определяющий уровень риска задачи: сигнал,
  потерянный при разборе, выглядит как «сигнал не сработал».
- **`jq` уже обязателен** — без него не работает ни валидатор плана
  (`scripts/plan.sh`), ни хук границ команд шага
  (`scripts/step-bash-allow.sh`). То есть JSON в этом репозитории читается
  средством, которое и так есть на каждой машине, где обвязка работает вообще.

Практическая разница для человека, который правит таблицу сигналов, невелика:
пути, регулярки и уровни выглядят в JSON почти так же. Комментарии в JSON
невозможны — их место занимает обязательное поле `note` у каждого сигнала, и
это скорее польза: причина живёт при сигнале, а не рядом с ним.

## Что осталось за пределами решения

**Раздел ТЗ не поправлен** — документ лежит вне репозитория, и правит его
владелец. Здесь зафиксировано расхождение, а не разрешение его игнорировать.

**Защита файла.** `pipeline/**` не входит ни в `.github/CODEOWNERS`, ни в
`scripts/protected-paths.sh`: сейчас конфиг ничего не блокирует и ни на что не
влияет, кроме печатаемого уровня, а сам едет в диффе PR и виден на ревью.
К фазе 7, когда уровень начнёт определять маршрут задачи, файл придётся
защитить — отдельной задачей, вместе с обеими сторонами списка.

## Следствия

- `pipeline/risk.json` — таблица сигналов и пороги размера;
- `scripts/risk-score.sh` — читает конфиг через `jq`, отказывает кодом 2 на
  сломанном или неполном конфиге;
- `scripts/risk-score.test.sh` — сценарии на отказ по сломанному конфигу и на
  полноту: перечень сигналов берётся из конфига, а не из списка в харнессе.
