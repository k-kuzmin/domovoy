# 0011. Список типов коммитов расширен до одиннадцати

**Статус:** принято

## Решение

Хук `commit-msg` и `.claude/CLAUDE.md` разрешают одиннадцать типов:
`feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `perf`, `build`, `ci`,
`revert`, `style`.

Постановка задачи перечисляет шесть: `feat`, `fix`, `chore`, `docs`,
`refactor`, `test`. Пять типов добавлены сверх её списка.

## Почему так

Все пять входят в спецификацию Conventional Commits, на которую
постановка и ссылается. Список из шести читается как сокращение, а не
как закрытый набор: без `ci` не описать правку рабочего процесса, без
`build` — правку `Directory.Build.props`, без `revert` — откат.

По каждому:

- `ci` — в проекте два рабочих процесса GitHub Actions, их правки
  начались на этапе 0 (коммит `25d0c8f`).
- `build` — есть `Directory.Build.props` и `Directory.Packages.props`,
  правки версий пакетов и настроек сборки не относятся ни к `chore`, ни
  к `feat`.
- `style` — есть отдельный шаг проверки стиля (`dotnet format`), правки
  только форматирования будут появляться регулярно. Хук отклонил первый
  же такой коммит, потому что типа не было в списке.
- `perf` — производительность вынесена в отдельные требования
  (NFR-PERF-1…7), и правка, которая только ускоряет, не меняя
  поведения, — это не `fix`.
- `revert` — git формирует такое сообщение сам, и хук пропускает его
  отдельной ветвью `case`; тип в списке нужен для ручного отката.

## Следствия

- Список в трёх местах: паттерн в `.githooks/commit-msg`, раздел «Git» в
  `.claude/CLAUDE.md` и текст сообщения об отказе того же хука. При
  изменении обновляются все три — расхождение между паттерном и текстом
  отказа уже случалось.
- Новый тип сверх спецификации Conventional Commits не добавляется:
  свои типы делают историю непригодной для автоматической обработки.
