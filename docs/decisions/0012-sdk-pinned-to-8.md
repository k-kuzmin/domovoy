# 0012. SDK зафиксирован на 8.0.x в `global.json`

**Статус:** принято, отменяет часть записи в «Стек и версии»

## Решение

В корне репозитория появился `global.json`:

```json
{
  "sdk": {
    "version": "8.0.100",
    "rollForward": "latestFeature",
    "allowPrerelease": false
  }
}
```

`rollForward: latestFeature` означает: подойдёт любой установленный SDK
`8.0.x` не ниже `8.0.100`, но не `9.x`. Сборка на девятом SDK больше
невозможна.

Раздел «Стек и версии» в `.claude/CLAUDE.md` до этого допускал «8.0 или
9.0». Запись отменяет это допущение.

## Почему так

Целевая платформа — `net8.0`, и девятый SDK собирает её через reference
packs корректно. Прежнее допущение было верным по существу, но оставляло
незакрытым различие, которое проявляется не в сборке, а в проверках.

`AnalysisLevel` в `Directory.Build.props` задан как `latest`. Это
означает «набор правил, актуальный для текущего SDK», то есть разный
набор под 8 и под 9. То же касается `dotnet format`: правила
форматирования и их реализация меняются между версиями.

Практическое следствие: разработчик с девятым SDK и CI с восьмым
проверяют не одно и то же. Расхождение проявляется не как ошибка, а как
`dotnet format --verify-no-changes`, который зелёный локально и красный в
CI, — то есть в момент, когда работа уже сделана.

Пайплайн, в котором агент итерируется по логам CI, делает это дороже:
агент правит по логу проверку, которую локально воспроизвести не может,
и тратит попытки на разницу версий инструмента, а не на дефект.

Фиксация убирает целый класс расхождений одной строкой.

## Альтернатива, которая рассматривалась

`rollForward: latestMajor` — фиксирует нижнюю границу и разрешает 9.x.
Сохраняет прежнюю гибкость и не требует ставить восьмой SDK туда, где
его нет.

Отклонена: она сохраняет ровно ту разницу в наборе анализаторов, ради
устранения которой запись и заводится. Гибкость здесь — это гибкость
получать разные результаты проверок на одном коммите.

## Следствия

- **На машине разработчика должен быть установлен SDK 8.0.x.** Без него
  любая команда `dotnet` в этом репозитории откажется работать с
  сообщением о несовместимости `global.json`. Установка:
  `winget install --id Microsoft.DotNet.SDK.8` (Windows),
  `brew install --cask dotnet-sdk@8` (macOS), пакеты дистрибутива (Linux).
- Рабочие процессы CI получают версию из `global.json`
  (`global-json-file`), а не из отдельного `dotnet-version`: источник
  истины один, разъехаться нечему.
- `Dockerfile` копирует `global.json` в слой восстановления пакетов —
  иначе `restore` в образе выполнялся бы под версией, которую файл не
  описывает. Базовый образ `mcr.microsoft.com/dotnet/sdk:8.0`
  ограничению удовлетворяет.
- Переход на `net10.0` (следующий LTS) потребует изменить этот файл
  осознанно и отдельной записью — что и требуется: смена SDK не должна
  происходить оттого, что кто-то обновил инструменты на своей машине.
