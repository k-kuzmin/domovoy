# 0004. В docker-compose только состав этапа 0

**Статус:** принято
**Расходится с:** раздел 3 ТЗ

## Расхождение

Раздел 3 ТЗ описывает развёртывание как «HA, backend, БД, ntfy, whisper
одним стеком». В `docker-compose.yml` сейчас только Backend и
PostgreSQL — состав, заданный этапом 0.

## Решение

Сервисы добавляются в compose тем этапом, который их использует: ntfy на
этапе 3, faster-whisper на этапе 4. Home Assistant остаётся отдельным —
он ставится и настраивается вручную, с реальными устройствами.

## Почему так

Требование «`docker compose up` на чистой машине поднимается на
example-конфигурации» сильнее требования полноты стека. Образ
faster-whisper весит несколько гигабайт и без модели бесполезен;
контейнер Home Assistant без проброшенных устройств и настроенной
интеграции поднимется, но ничем не управляет. Стек, который скачивает
гигабайты и не работает, проверку «поднимается на чистой машине» не
проходит по существу, даже если формально стартует.

## Следствия

- Каждый этап, добавляющий сервис, обновляет `docker-compose.yml`, пример
  переопределений, health-check и схему в README — это записано в
  таблицу синхронизации.
- Адреса Home Assistant и STT в конфигурации указывают на имена сервисов
  Docker, поэтому появление сервисов не потребует правки формата
  настроек.
