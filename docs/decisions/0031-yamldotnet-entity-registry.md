# 0031. Реестр сущностей разбирается YamlDotNet

**Статус:** принято

## Контекст

Реестр сущностей — allow-list (FR-HA-4, FR-HA-5): сущность, не попавшая в
него, невидима для модели и не может быть изменена. Формат файла — YAML: его
задают критерий задачи #10 (`config/entities.example.yaml`) и ТЗ 5.1.3.

Встроенного разборщика YAML в .NET 8 нет. Набор зависимостей проекта закрытый
(`.claude/CLAUDE.md`, «Зависимости»): новая библиотека требует обоснования в
issue до установки. Обоснование опубликовано в #10
([комментарий](https://github.com/k-kuzmin/domovoy/issues/10#issuecomment-6170265212)),
согласие владельца получено в сессии задачи #9.

## Решение

Файл реестра разбирает [YamlDotNet](https://github.com/aaubry/YamlDotNet)
**18.1.0** — последняя стабильная версия на момент установки (2026-10-14),
закреплена в `Directory.Packages.props`. Пакет ставится только в
`Domovoy.Ha`: Core о формате файла не знает.

Разбор строгий: ключи — snake_case (`UnderscoredNamingConvention`),
незнакомый ключ — ошибка разбора, а не молча пропущенное поле. Ошибка
разбора — отказ старта через `IValidateOptions` и `ValidateOnStart`.

## Отвергнуто

- **Свой разбор YAML.** Запрещён правилом «Не изобретать своё»: самописный
  парсер ошибается молча, а этот файл определяет, какие сущности видит агент.
- **JSON вместо YAML.** Встроенный `System.Text.Json` закрыл бы вопрос
  зависимости, но формат реестра задан критерием #10 и ТЗ 5.1.3; к тому же
  YAML допускает комментарии, а пример реестра ими объясняет решения
  владельца.

## Следствия

- Тот же разборщик используют `config/response-templates.yaml` (#23) и
  `config/proactive-rules.yaml` (#31) — новой зависимости для них не нужно.
