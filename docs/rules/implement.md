# Реализация

План согласован человеком — можно писать код. План при этом обязательство, а
не набросок: расхождение с ним описывается в PR отдельным абзацем.

Правила проекта — `.claude/CLAUDE.md`, читать из репозитория, а не по памяти.
Обязательны к исполнению разделы «Архитектура», «Границы работы агента»,
«Запрещённые способы „починить“ сборку», «Правила синхронизации», «Git»,
«Журнал задачи», «Definition of Done».

## Порядок работы

1. **Ветка от `main`:** `feat/<номер задачи>-краткое-описание`, описание
   латиницей, через дефис, три-четыре слова. Если ветка с таким именем уже
   существует, работа продолжается в ней: предыдущий заход мог оборваться, и
   терять его коммиты нельзя.
2. **Журнал.** Завести `docs/tasks/<номер>.md` из `docs/tasks/TEMPLATE.md` —
   или открыть существующий, если его создал предыдущий заход. Перенести в
   него границы задачи и согласованный план. Дальше журнал заполняется по
   ходу работы, а не в конце: «Решения» — когда решение принято, «Изменённые
   файлы» — когда файл изменён.
3. **Сначала тесты.** Написать тест, проверяющий требуемое поведение,
   убедиться, что он падает по существу, и только потом писать код. Тест,
   который проходит при сломанной реализации, хуже отсутствующего.
4. **Проверять по ходу.** После каждого осмысленного шага:

       dotnet build --no-restore -c Release
       dotnet test --no-build -c Release

   Ещё две команды — не на каждом шаге, а по поводу:

       dotnet restore                                  # менялись *.csproj или Directory.Packages.props
       dotnet format --verify-no-changes --no-restore  # перед коммитом

   `restore` не может дать другой результат, пока файлы проекта не изменились,
   а проверка стиля осмысленна перед фиксацией, а не после каждой правки.
   Каждый лишний прогон — лишний ход, а ход пересылает весь накопленный
   контекст.

   Красное чинится сразу, до следующего шага. Не копить правки в надежде, что
   сборка соберётся в конце. **Перед пушем прогоняются все четыре.**
5. **Коммитить по ходу.** Conventional Commits, один коммит — одно логическое
   изменение. Без трейлеров `Co-Authored-By`, упоминаний генерации и подписей
   инструментов: это проверяет хук `commit-msg` и отдельная работа в CI.
6. **Синхронизация.** Обновить то, что перечислено в таблице «Правила
   синхронизации» в `CLAUDE.md`: `.env.example`, `appsettings.json`, README,
   docker-compose, описание инструмента в системном промпте — по тому, что
   реально изменилось.
7. **Ветка и черновой PR.** Запушить ветку и открыть **черновой** PR
   (`gh pr create --draft`) с телом, содержащим строку `Closes #<номер>`,
   краткое описание изменения и список того, что осталось за рамками. Если
   черновой PR уже открыт предыдущим заходом, обновляется его тело, а не
   создаётся новый. Ревью запускает человек, снимая с PR черновик.
8. **Последним действием** обновить в шапке журнала стадию и строку
   `Следующий шаг`. Она адресована не тебе, а тому, кто продолжит работу с
   чистого листа, — и обновляется всегда, даже когда больше ничего не
   изменилось.

## Чего делать нельзя

Список запретов — раздел «Запрещённые способы „починить“ сборку» в
`.claude/CLAUDE.md`. Он здесь не пересказывается: копия правила разъезжается
с источником молча.

Сверх него, на этом шаге:

- **выходить за рамки задачи** — замеченная попутно проблема идёт новой issue,
  а не правкой в этом диффе;
- **добавлять зависимости** — любая новая библиотека требует обоснования в
  issue до установки.

Если задача требует правки защищённого пути, а метки `agent/allow-protected`
на ней нет (для контракта API — `agent/allow-contract`), защищённый путь не
правится. Гейт целостности `scripts/guard.sh` всё равно завернёт такой PR.
Сделать остальное и написать в PR, что именно осталось и какой метки не
хватает.

Задача не сходится по существу — остановиться и написать об этом в PR или в
комментарии к задаче. Остановка с объяснением — нормальный результат. Зелёная
сборка, добытая подавлением, — нет.
