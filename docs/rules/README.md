# Правила шагов работы

`.claude/CLAUDE.md` отвечает на вопрос «что в этом проекте можно и нельзя».
Файлы здесь отвечают на другой: **на что смотреть на конкретном шаге работы** —
какие критерии у триажа, из чего состоит план, в каком порядке идёт реализация,
что проверяет ревью, чем починка отличается от её имитации.

Эти правила — слой поверх `CLAUDE.md`, а не замена ему. Ни один файл здесь не
пересказывает раздел `CLAUDE.md`: где правило уже записано там, здесь стоит
ссылка. Копия правила хуже отсутствующей ссылки — она разъезжается молча.

## Зачем отдельный каталог

Правила шагов раньше жили внутри промптов `.github/workflows/agent-*.yml`.
Для агентского цикла этого достаточно: пять процессов — пять запусков, каждый
читает свой промпт. Но **основной режим работы другой** — задачу ведёт человек
из Claude CLI (`docs/pipeline.md`), а локальная сессия в `.github/**` не
заходит вовсе: это защищённый путь, который она не правит и без повода не
открывает.

Получалось, что метод работы существовал только для спящих процессов. Живой
режим, в котором и делается вся работа, о нём не знал.

Источник теперь один. Промпты `agent-*.yml` ссылаются на эти файлы, а не
дублируют их.

## Какой файл к какому шагу

| Шаг | Правила | Процесс |
|---|---|---|
| Триаж | [`triage.md`](triage.md) | `agent-triage.yml` |
| План | [`plan.md`](plan.md) | `agent-plan.yml` |
| Реализация | [`implement.md`](implement.md) | `agent-implement.yml` |
| Ревью — корректность | [`review-correctness.md`](review-correctness.md) | `agent-review.yml`, job `correctness` |
| Ревью — безопасность | [`review-security.md`](review-security.md) | `agent-review.yml`, job `security` |
| Починка | [`fix.md`](fix.md) | `agent-fix.yml` |
| Любой шаг | [`reading.md`](reading.md) | все `agent-*.yml` |

Ревью разнесено на два файла не для порядка в каталоге. В `agent-review.yml`
это два независимых job с разными промптами, и разделены они намеренно:
ревьюер, которого попросили посмотреть «и корректность, и безопасность»,
заканчивает список после третьего пункта. Один файл на два job вернул бы ровно
это.

**Локальная сессия читает оба.** В CI их разделяют два запуска, в разговоре
делить нечем — а список «не применимо сейчас» живёт только в половине про
безопасность, и без него ревью выписывает замечания про Secure Storage и права
Android, которых в репозитории нет.

`reading.md` — единственная строка таблицы без своего процесса, потому что
процесса у него и нет. Читать объёмный вывод приходится на всех шагах, а
значит правило нужно всем пяти промптам, а не какому-то одному. Промпт, в
котором этого файла нет, — это шаг, чей агент правило не откроет; каталог
написан ровно против такого расклада.

## Уровни замечаний

Общие для обоих файлов ревью.

| Уровень | Что означает |
|---|---|
| **blocker** | Мержить нельзя: расхождение с критерием приёмки, сломанное поведение, подавленная проверка |
| **major** | Надо исправить, но не обязательно в этом PR |
| **nit** | Вкусовое, автор вправе не согласиться |

У каждого замечания — путь к файлу, номер строки и то, что конкретно сделать.
«Стоит подумать об обработке ошибок» — не замечание.

Замечаний нет — так и написать. Пустое ревью честнее придуманного nit.
