# Правила шагов работы

`.claude/CLAUDE.md` отвечает на вопрос «что в этом проекте можно и нельзя».
Файлы здесь отвечают на другой: **на что смотреть на конкретном шаге работы** —
какие критерии у триажа, из чего состоит план, в каком порядке идёт реализация,
что проверяет ревью, чем починка отличается от её имитации.

Эти правила — слой поверх `CLAUDE.md`, а не замена ему. Ни один файл здесь не
пересказывает раздел `CLAUDE.md`: где правило уже записано там, здесь стоит
ссылка. Копия правила хуже отсутствующей ссылки — она разъезжается молча.

## Зачем отдельный каталог

Правила шагов раньше жили внутри промптов `.github/workflows/agent-*.yml`.
Для агентского цикла этого достаточно: пять процессов — пять запусков, каждый
читает свой промпт. Но **основной режим работы другой** — задачу ведёт человек
из Claude CLI (`docs/pipeline.md`), а локальная сессия в `.github/**` не
заходит вовсе: это защищённый путь, который она не правит и без повода не
открывает.

Получалось, что метод работы существовал только для спящих процессов. Живой
режим, в котором и делается вся работа, о нём не знал.

Источник теперь один. И промпты `agent-*.yml`, и определения субагентов
`.claude/agents/step-*.md` ссылаются на эти файлы, а не дублируют их.

## Какой файл к какому шагу

| Шаг | Правила | Процесс цикла | Определение локального субагента |
|---|---|---|---|
| Триаж | [`triage.md`](triage.md) | `agent-triage.yml` | `step-triage.md` |
| План | [`plan.md`](plan.md) | `agent-plan.yml` | `step-plan.md` |
| Реализация | [`implement.md`](implement.md) | `agent-implement.yml` | `step-implement.md` |
| Ревью — корректность | [`review-correctness.md`](review-correctness.md) | `agent-review.yml`, job `correctness` | `step-review-correctness.md` |
| Ревью — безопасность | [`review-security.md`](review-security.md) | `agent-review.yml`, job `security` | `step-review-security.md` |
| Починка | [`fix.md`](fix.md) | `agent-fix.yml` | `step-fix.md`, `step-fix-flaky.md` |
| Любой шаг | [`reading.md`](reading.md) | все `agent-*.yml` | все `step-*.md` |

Определения лежат в `.claude/agents/`. У починки их две штуки на одну строку
таблицы — почему, сказано в `.claude/CLAUDE.md`, раздел «Правила шагов
работы». Файл правил у обеих один и тот же: [`fix.md`](fix.md), раздел
«Случайное падение».

Ревью разнесено на два файла не для порядка в каталоге. В `agent-review.yml`
это два независимых job с разными промптами, и разделены они намеренно:
ревьюер, которого попросили посмотреть «и корректность, и безопасность»,
заканчивает список после третьего пункта. Один файл на два job вернул бы ровно
это.

**Локально их читают тоже двое.** В CI половины разделяют два job, локально —
два определения субагентов, `step-review-correctness.md` и
`step-review-security.md`, каждое с чистым контекстом и своим файлом правил.
Раньше делить было нечем, и одна сессия читала оба файла подряд; чем это
кончалось, видно из абзаца выше. Список «не применимо сейчас» живёт только в
половине про безопасность — её субагент читает его целиком, иначе ревью
выписывает замечания про Secure Storage и права Android, которых в репозитории
нет.

`reading.md` — единственная строка таблицы без своего процесса и без своего
определения: шага у него и нет. Читать объёмный вывод приходится везде, а
значит ссылка на него нужна каждому потребителю — всем пяти промптам и всем
семи определениям, а не какому-то одному из них. Потребитель, где этого файла
нет, — это шаг, чей агент правило не откроет; каталог написан ровно против
такого расклада.

Это уже не пожелание. `rules-sync.sh` считает общим любое правило, к имени
которого не сходится ни один шаг, и требует ссылку на него у каждого
потребителя — прогон краснеет, а не молчит.

## Уровни замечаний

Общие для обоих файлов ревью.

| Уровень | Что означает |
|---|---|
| **blocker** | Мержить нельзя: расхождение с критерием приёмки, сломанное поведение, подавленная проверка |
| **major** | Надо исправить, но не обязательно в этом PR |
| **nit** | Вкусовое, автор вправе не согласиться |

У каждого замечания — путь к файлу, номер строки и то, что конкретно сделать.
«Стоит подумать об обработке ошибок» — не замечание.

Замечаний нет — так и написать. Пустое ревью честнее придуманного nit.
