## Решения

**Четыре ветки — четыре функции.** `gh_repo_pointer` + `gh_repo_value_check`, `gh_address_check`, `gh_expression_check`, `gh_search_word_check` + `gh_search_scope_check`. У каждой одна точка выключения: мутация — правка одной строки внутри ветки `gh`, остальная граница не задевается.

**Разбор gh стоит после поимённых флагов.** У `--label`, `-l`, `--output` свои причины отказа, и они называются первыми: сценарий «метка сцепкой коротких флагов» ждёт в выводе именно `-l`.

**Слаг выводится лениво.** `git remote get-url origin` зовётся только тогда, когда слово требует слага. Голый `gh issue view 1` git не зовёт.

**`-R` ловится шаблоном в два шага.** Первая версия `-[!-]*R*` не ловила голое `-R`: класс `[!-]` съедал саму R. Сценарии «чужой --repo» и «второй указатель» покраснели на `-R чужой/репо`, после перехода на приём `-l` (`-[!-]*`, затем `*R*`) — зелёные.

**Сверх плана, тот же класс в том же выражении:**

- адрес в scp-форме `git@github.com:o/r` считается адресом GitHub;
- квалификатор `owner:` отбивается наравне с `repo:`, `org:`, `user:`;
- `--repo` без значения — отказ;
- адрес без второго сегмента пути (`https://github.com/acme-qt`) своим не считается.

**Сокращение `--jq`.** У `--jq` нет сокращения длиной от четырёх символов, отличного от него самого, поэтому `is_flag` его и не ищет. Сокращение проверено на `--templ`.

**Поддельный слаг — `acme-qt/tool-repo`** (поправка 1 ревью круга 2). Положительные написания: `ACME-QT/Tool-Repo`, `-R<слаг>`, `-cR<слаг>`, `-cR <СЛАГ>`. Буквы q и t после R на `-q`/`-t` не проверяются, и это видно по молчанию на `-cRacme-qt/tool-repo`. Кириллица стоит только в чужих значениях.

**Каталог без origin — репозиторий после `git init`.** Из просто временного каталога git поднялся бы к родителю и нашёл бы чужой origin.

**`owner-comments.sh` помечает последний комментарий владельца явно** («— последний»). Правило берёт последний из комментариев владельца, а строка тела, повторяющая форму заголовка, остаётся внутри блока с префиксом `  | `.

## Осталось

**Мутационная серия — человеку.** Классификатор режима auto дважды отклонил прогон харнесса на правленной рабочей копии: первый раз — харнесса выборки («Security Weaken»), второй — границы («Self-Modification»). Обе правки откачены через `Edit`, `git status` чист. Серия — восемь прогонов. Каждый прогон: правка → `bash scripts/step-bash-allow.test.sh | grep -E '^\[ FAIL\]|^Сценариев'` → `git checkout -- scripts/step-bash-allow.sh` → `git status` чист.

Прямые мутации (ветка выключена):

| Ветка | Правка | Ожидаемые `[ FAIL]` (предсказание, не прогон) |
|---|---|---|
| указатель | первой строкой `gh_repo_pointer` — `return 1` | «чужой --repo», «-R в сцепке с чужим», «второй указатель после своего», «issue-scout: второй указатель», «слаг не выведен — отказ»; и два случая с молчанием — «gh search со своим --repo», «issue-scout: пришпиленные»: `own_pointer` выставляет ветка указателя, и без неё поиск считается поиском без --repo |
| адрес | первой строкой `gh_address_check` — `return 0` | «чужой адрес», «в другом написании», «префикс-подделка», «слаг не выведен — отказ», «issue-scout: второй указатель» |
| выражение | первой строкой `gh_expression_check` — `return 0` | «выражение над ответом — отказ» |
| поиск | первой строкой `gh_search_word_check` и `gh_search_scope_check` — `return 0` | «gh search без своего --repo — отказ» |

Обратные мутации (ветка отказывает безусловно):

| Ветка | Правка | Ожидаемые `[ FAIL]` (предсказание, не прогон) |
|---|---|---|
| указатель | в `gh_repo_value_check` `if ! is_own_slug "$1"` → `if true` | «свой --repo», «-R в сцепке со своим», «gh search со своим --repo», «issue-scout: пришпиленные» |
| адрес | в `gh_address_check` условие отказа → `if true` | «свой адрес github.com — молчание» |
| выражение | первой строкой `gh_expression_check` — `deny мутация` | все случаи с молчанием на `gh`, включая «команды из правил шагов» |
| поиск | в `gh_search_scope_check` `[ "$2" -eq 0 ]` → `true` | «gh search со своим --repo», «issue-scout: пришпиленные» |

Случай «адрес другого хоста и слово github.com без пути — молчание» краснеет только от обратной мутации выражения. Там он краснеет потому, что отказ получает любая часть `gh`, а не из-за разбора адреса.

**Красный прогон харнесса выборки — человеку.** Правка в `scripts/owner-comments.sh`: `select(.authorAssociation == "OWNER")` → `select(true)`. Команда: `bash scripts/owner-comments.test.sh | grep -E '^\[ FAIL\]|пройдено'`. Ожидается хотя бы один красный случай — «выборка владельца: подделка чужим автором не печатается». Откат: `git checkout -- scripts/owner-comments.sh`.

**Закрытие.** Пока серия и красный прогон выборки не вписаны в журнал, в теле PR стоит `Part of #119`. После них строку заменить на `Closes #119`.

**Живого прогона `bash scripts/owner-comments.sh` нет.** Сценарий не выдан шагу реализации, его проверяет только харнесс. Контракт этого не требует.

## Попутные находки

- **Цикловая половина.** `--allowedTools 'Bash(gh issue view:*)'` в `.github/workflows/agent-*.yml` хук не вызывает. В цикле `--jq` и чужой `--repo` по-прежнему проходят. Записано в шапке границы.
- **Слова, собранные оболочкой.** Нормализация снимает кавычки, но не исполняет оболочку. Поэтому `--j\q`, `--j${x:-q}` и `$'--jq'` по нормализованной части не узнаются. Это касается всех поимённых флагов, включая `--no-verify`. Вывод сделан по разбору кода, прогона не было: живой прогон был бы эксплуатацией. Записано в шапке границы.
- **Устаревшее обоснование** в шапке `scripts/review-comments.sh:19–21`: «разбор аргументов … дальше поимённых флагов не идёт». После #119 у `gh` разбираются указатель, адрес и выражение. Вывод «`gh api` не выдаётся» остаётся верным: `-X` и `--input` не разбираются.
- **Уровень риска пачки.** `bash scripts/risk-score.sh diff origin/main HEAD` на `36d1901`: **high**. Файлов 25 при пороге 11, строк 2390 при пороге 1538, подсистем 8. Сигналы: `sensitive-area` (слово `Authoriz` в тесте #126), `app-configuration`, `diff-size`, `work-breadth`.
