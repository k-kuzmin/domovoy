«размер диффа» и «ключевые слова» и называет строки: «размер диффа по строкам
и ключевые слова по добавленным строкам … Размер по числу файлов считается по

**Исключение IF [NOT] EXISTS — вторым фильтром в bash, а не шаблоном.** В awk
нет отрицательного просмотра вперёд, и «без IF EXISTS на той же строке» одним
шаблоном `select_lines` не выражается. Строка, отобранная правилом, приводится
к нижнему регистру (`${text,,}`) и сверяется с исключением правила.

**`select_lines` получил четвёртый необязательный параметр.** Существующие
вызовы не менялись; переменная признака выставляется на каждом вызове, поэтому
значение проверки 9 в проверки 2-4 не протекает.

96-5)** — замерено после круга 4, а не выведено: `gh pr diff` шагу не выдан,

    60:-            if (text ~ pat) print $2 "\t" $3 "\t" text

    94:-            "Деструктивная операция в миграции: $file. Удаление и переименование столбцов и таблиц необратимо теряет данные и ломает работающий экземпляр при откате. сравнение `text ~ pat`, ставшее сравнением копии `cmp`. Две — в блоке проверки
4, и у каждой есть добавленная замена (строки 86 и 95 того же диффа):

- `DESTRUCTIVE_RE` — `(DropColumn|DropTable|RenameColumn|RenameTable|AlterColumn|AddPrimaryKey)`:

- сообщение — три прежних предложения («Деструктивная операция в миграции:
  $file.», «Удаление и переименование … при откате.», «Нужна метка … плана
  переноса.») стоят дословно, между вторым и третьим вставлено «Добавление
  первичного ключа (AddPrimaryKey) на живой таблице перестраивает её под
  блокировкой и падает на дублях.»

Строки «вызов API EF AddPrimaryKey не ловится ни здесь, ни в проверке 4» в
