## Решения

Решения и отвергнутые варианты — раздел 2 плана круга 3. Здесь — то, что
принято по ходу реализации.

**Сначала красный.** Сценарий «Анонимный эндпоинт опознаётся словом
allowanonymous…» до правки конфига падал по существу: `Уровень: low`, сигнала
`sensitive-area` нет, строки `слово: AllowAnonymous — …` нет (харнесс 39 из 40).
После правки — 40 из 40.

**Контрольный прогон без слова — через `mutate_config`.** Конфиг настоящий, из
него вычитается ровно `allowanonymous`: молчание на том же диффе доказывает,
что high держится на слове, а не на чужом совпадении в тех же строках.

**Размер плана: сначала красный.** Три сценария до правки движка падали по
существу (харнесс 39 из 42): план на 12 файлов давал `low` без `diff-size`,
незаданный порог файлов в plan молчал, строки «по строкам» в выводе не было.
После правки — 42 из 42. Текст «Не измерялось в режиме plan» сохраняет
«размер диффа» и «ключевые слова» и называет строки: «размер диффа по строкам
и ключевые слова по добавленным строкам … Размер по числу файлов считается по
files[] плана».

**Строка о незаданном пороге размера в plan — по порогу файлов.** Диффу нужны
оба порога, плану — только `diff_files`: строк у него нет, и незаданный
`diff_lines` на счёт плана не влияет.

**Проверка 8: сначала красный.** До правки `guard.sh` четыре новых сценария
падали по существу (харнесс 29 из 33), и сценарий обхода из #90 —
опустошённый `[InlineData]` плюс подложенный `TestResults/pad.trx` — давал код
0: дыра воспроизведена на дереве до правки. После правки — 33 из 33.

**Проверка 8 при выключенном блоке (90-2, 90-3).** Настоящая версия
`guard.sh` застейджена, в рабочем дереве после цикла отбора добавлена строка,
опустошающая список попаданий, прогон `bash scripts/guard.test.sh`, затем
`git checkout -- scripts/guard.sh` — рабочее дерево совпало с индексом,
выключенная версия не коммитилась. Строки прогона:

    [ FAIL] проверка 8: закоммиченный trx-отчёт — гейт падает
    [ FAIL] проверка 8: отчёт прогона не снимается ни одной меткой
    [ FAIL] проверка 8: файл под каталогом результатов прогона — гейт падает
    [ FAIL] проверка 8: опустошённый [InlineData] и подложенный отчёт — гейт падает на проверке 8
    [ ok  ] проверка 8: удаление ранее закоммиченного отчёта — гейт молчит
    Сценариев пройдено: 29, провалено: 4, пропущено: 0

Сценарий удаления зелёный и при выключенной проверке — ожидаемо: он про
отсутствие ложной тревоги. После возврата — 33 из 33.

**Порядок формулировок проверки 8.** Путь с окончанием `.trx` получает
формулировку «отчёт о прогоне» даже под каталогом результатов; остальные файлы
под каталогом — «файл под каталогом результатов». Нарушение одно: на путь одна
аннотация.

**Свой вызов `git diff --diff-filter=d` для проверки 8**, а не `CHANGED_FILES`:
тот включает удаления, а удаление ранее закоммиченного отчёта — починка.

**Строки, удалённые в `guard.sh` вне блоков проверок.** Одна строка шапки
«ПЕРЕЧЕНЬ И ИНВАРИАНТ» переписана: «диффовая половина — проверка 7» стала
«проверки 7 и 8». В блоках проверок 1-7 и в массивах `SUPPRESSION_PATTERNS` и
`SUPPRESSION_LABELS` удалённых строк нет.
