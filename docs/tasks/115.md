## Решения

Решения и отвергнутые варианты — раздел 2 плана круга 3. Здесь — то, что
принято по ходу реализации.

**Сначала красный.** Сценарий «Анонимный эндпоинт опознаётся словом
allowanonymous…» до правки конфига падал по существу: `Уровень: low`, сигнала
`sensitive-area` нет, строки `слово: AllowAnonymous — …` нет (харнесс 39 из 40).
После правки — 40 из 40.

**Контрольный прогон без слова — через `mutate_config`.** Конфиг настоящий, из
него вычитается ровно `allowanonymous`: молчание на том же диффе доказывает,
что high держится на слове, а не на чужом совпадении в тех же строках.

**Размер плана: сначала красный.** Три сценария до правки движка падали по
существу (харнесс 39 из 42): план на 12 файлов давал `low` без `diff-size`,
незаданный порог файлов в plan молчал, строки «по строкам» в выводе не было.
После правки — 42 из 42. Текст «Не измерялось в режиме plan» сохраняет
«размер диффа» и «ключевые слова» и называет строки: «размер диффа по строкам
и ключевые слова по добавленным строкам … Размер по числу файлов считается по
files[] плана».

**Строка о незаданном пороге размера в plan — по порогу файлов.** Диффу нужны
оба порога, плану — только `diff_files`: строк у него нет, и незаданный
`diff_lines` на счёт плана не влияет.

**Проверка 8: сначала красный.** До правки `guard.sh` четыре новых сценария
падали по существу (харнесс 29 из 33), и сценарий обхода из #90 —
опустошённый `[InlineData]` плюс подложенный `TestResults/pad.trx` — давал код
0: дыра воспроизведена на дереве до правки. После правки — 33 из 33.

**Проверка 8 при выключенном блоке (90-2, 90-3).** Настоящая версия
`guard.sh` застейджена, в рабочем дереве после цикла отбора добавлена строка,
опустошающая список попаданий, прогон `bash scripts/guard.test.sh`, затем
`git checkout -- scripts/guard.sh` — рабочее дерево совпало с индексом,
выключенная версия не коммитилась. Строки прогона:

    [ FAIL] проверка 8: закоммиченный trx-отчёт — гейт падает
    [ FAIL] проверка 8: отчёт прогона не снимается ни одной меткой
    [ FAIL] проверка 8: файл под каталогом результатов прогона — гейт падает
    [ FAIL] проверка 8: опустошённый [InlineData] и подложенный отчёт — гейт падает на проверке 8
    [ ok  ] проверка 8: удаление ранее закоммиченного отчёта — гейт молчит
    Сценариев пройдено: 29, провалено: 4, пропущено: 0

Сценарий удаления зелёный и при выключенной проверке — ожидаемо: он про
отсутствие ложной тревоги. После возврата — 33 из 33.

**Порядок формулировок проверки 8.** Путь с окончанием `.trx` получает
формулировку «отчёт о прогоне» даже под каталогом результатов; остальные файлы
под каталогом — «файл под каталогом результатов». Нарушение одно: на путь одна
аннотация.

**Свой вызов `git diff --diff-filter=d` для проверки 8**, а не `CHANGED_FILES`:
тот включает удаления, а удаление ранее закоммиченного отчёта — починка.

**Строки, удалённые в `guard.sh` вне блоков проверок.** Одна строка шапки
«ПЕРЕЧЕНЬ И ИНВАРИАНТ» переписана: «диффовая половина — проверка 7» стала
«проверки 7 и 8». В блоках проверок 1-7 и в массивах `SUPPRESSION_PATTERNS` и
`SUPPRESSION_LABELS` удалённых строк нет.

**Проверка 9: сначала красный.** До реализации три положительных сценария
падали (харнесс 35 из 38): пять правил, смешанный регистр, метка. Сценарии на
отсутствие ложной тревоги были зелёными и до правки — ожидаемо. После — 38 из
38.

**Проверка 9: пять нейтрализаций (96-4).** Каждый раз настоящая версия
застейджена, нейтрализация — правкой рабочего дерева, прогон
`bash scripts/guard.test.sh`, возврат `git checkout -- scripts/guard.sh`;
выключенные версии не коммитились. После возврата — 38 из 38.

(а) блок проверки 9 — список попаданий опустошён после отбора:

    [ FAIL] проверка 9: каждое из пяти правил B.4 ловится на добавленной строке и называет себя
    [ FAIL] проверка 9: SQL в смешанном регистре ловится так же
    [ FAIL] проверка 9: разрушительный SQL с меткой agent/allow-destructive-migration — гейт пропускает
    Сценариев пройдено: 35, провалено: 3, пропущено: 0

(б) исключение IF [NOT] EXISTS снято:

    [ FAIL] проверка 9: идемпотентные IF NOT EXISTS и DROP … IF EXISTS не срабатывают
    Сценариев пройдено: 37, провалено: 1, пропущено: 0

(в) ведущая граница truncate снята — сработало на строке 8 фикстуры,
`var shouldTruncate = false;`:

    [ FAIL] проверка 9: идентификаторы EF со словом Truncate не срабатывают
    Сценариев пройдено: 37, провалено: 1, пропущено: 0

(г) замыкающая граница truncate снята — сработало на
`b.Property<int>("TruncateAfter");` в Designer.cs и `text.Truncate(80);`:

    [ FAIL] проверка 9: идентификаторы EF со словом Truncate не срабатывают
    Сценариев пройдено: 37, провалено: 1, пропущено: 0

(д) признак «без регистра» снят у вызова `select_lines` проверки 9 — шаблоны в
нижнем регистре перестали совпадать с SQL в верхнем, поэтому покраснел не
только сценарий смешанного регистра:

    [ FAIL] проверка 9: каждое из пяти правил B.4 ловится на добавленной строке и называет себя
    [ FAIL] проверка 9: SQL в смешанном регистре ловится так же
    [ FAIL] проверка 9: разрушительный SQL с меткой agent/allow-destructive-migration — гейт пропускает
    Сценариев пройдено: 35, провалено: 3, пропущено: 0

**Исключение IF [NOT] EXISTS — вторым фильтром в bash, а не шаблоном.** В awk
нет отрицательного просмотра вперёд, и «без IF EXISTS на той же строке» одним
шаблоном `select_lines` не выражается. Строка, отобранная правилом, приводится
к нижнему регистру (`${text,,}`) и сверяется с исключением правила.

**`select_lines` получил четвёртый необязательный параметр.** Существующие
вызовы не менялись; переменная признака выставляется на каждом вызове, поэтому
значение проверки 9 в проверки 2-4 не протекает. Удалённая строка в функции
одна — сравнение `text ~ pat` стало сравнением копии `cmp`.

**Порядок версий миграций (96-3) — отложен.** Причина записана в шапке
проверки 9 в `scripts/guard.sh`: миграций в дереве ноль; посылка правила
(forward-only схема пропускает файл с меткой ниже текущей) для EF не
установлена — EF применяет пропущенные миграции; предмет другой — имена файлов
против истории базы. Адрес — новая задача, её заводит оркестратор после
выжимки `issue-scout`: #96 закрывается этим PR.

**`note` сигнала `db-migration` — в коммите #96**, а не #115: до проверки 9
фраза «SQL ловит проверка 9» была бы ложной.

## Осталось

- **Правило 7 `.claude/CLAUDE.md`** — перечень анонимных эндпоинтов с
  отсылками (`GET /health` → 0002, `POST /api/v1/auth/device` → 0025), без
  числа. Правит оркестратор в этой ветке до ревью: шагу реализации правка
  `.claude/CLAUDE.md` не положена. До неё 116-count и 116-links не выполнены.
- **Метка `agent/allow-protected` на PR** — без неё «Гейт целостности»
  красный: дифф трогает `pipeline/**`, `scripts/**`, `docs/rules/**`,
  `docs/decisions/**`. Ставит человек.
- **Новая задача на проверку порядка версий миграций** — заводит оркестратор
  после выжимки `issue-scout`.
