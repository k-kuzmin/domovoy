## Решения

**Триаж (2026-10-14).** `step-triage`: ready=false, один вопрос — где живёт
обнаружение отставания ветки, пока PR ждёт мерджа: исходом `merge-wait.sh`,
только шагом правила или тем и другим. Оркестратор сузил вопрос до
публикации: одно правило пункт 2 issue («узнаёт сам, а не от владельца») не
выполняет — пока PR ждёт мерджа, оркестратор бездействует и сверку не
запускает. Факт для выбора: ruleset `main` требует свежую ветку
(`required_status_checks`, `strict_required_status_checks_policy: true`),
поэтому GitHub отдаёт `mergeStateStatus` `BEHIND` и сам не даёт смерджить
отставший PR.

**Ответ владельца (2026-10-14).** Исход `BEHIND` в `merge-wait.sh` (по
`mergeStateStatus`). Сверка перед отдачей (`git fetch`,
`git log HEAD..origin/main`) — шаг правила п. 10–11 `.claude/CLAUDE.md`,
напоминание — впрыском правил `.claude/hooks/rules-map.json`.

**Совет, круг 1 (2026-10-14).** Страж и прагматик — `no_objections`,
скептик и инженер — `another_round`; блокеров нет. Замечание скептика «у
открытого PR вместо BEHIND может быть BLOCKED» сверено с ruleset: одобрений
не требуется (`required_approving_review_count: 0`), обязательны шесть
проверок CI — после зелёного CI BLOCKED по ревью не возникает. Все замечания
переданы шагу плана дословно.

**Совет, круг 2 (2026-10-14).** Все четверо — `no_objections`, только nit.
Nit скептика «jq при null даёт `OPEN` без пробела» снят прогоном:
`jq -n '{state:"OPEN",mergeStateStatus:null} | .state + " " + .mergeStateStatus'`
печатает `"OPEN "` с хвостовым пробелом — как в плане.

## Отвергнуто

- Только шаг правила без сценария — не выполняет пункт 2 issue: отставание
  во время ожидания мерджа по-прежнему замечает владелец.
- Сверка через `gh api …/compare` (`behind_by`) — от настройки ruleset не
  зависит, но добавляет вызов API на каждый опрос; владелец выбрал
  `mergeStateStatus`.

## Шаги

- Воспроизведение — сценарий «OPEN BEHIND» в `scripts/merge-wait.test.sh`,
  красный до реализации: `stdout «MERGED», ожидался ровно «BEHIND»`, 18 из 19.
  Вторая половина дефекта (нет сверки в п. 10 `.claude/CLAUDE.md`) — текст
  правила, тестом сценария не воспроизводится.
- Совет по плану — уровень high, полный состав (скептик, инженер, страж,
  прагматик). Признаки: правка обвязки, повторный дефект. Общий механизм —
  `merge-wait.sh` зовётся только из п. 11 `.claude/CLAUDE.md` и
  `docs/pipeline.md`, других вызывающих нет.
- Исход `DIRTY` план добавил сверх ответа владельца (тот же класс: main ушёл
  вперёд с конфликтом) — на подтверждение владельцу при просмотре плана.
