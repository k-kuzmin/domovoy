## Решения

**Триаж (2026-10-11).** `ready`, вопросов владельцу нет. Сверено
оркестратором: раздел «## Статус» в README есть, майлстоуны 1–7 — «Этап 0…
Этап 6», ветки `status` на origin нет. Способы проверки: картинка и ссылка в
разделе «Статус» — чтением README; обновление без коммита в `main` —
наблюдением прогона workflow и истории `origin/status` после закрытия задачи;
права и закреплённые версии — грепом `permissions`, `secrets.`, `uses:` по
workflow; светлая и тёмная тема — наблюдением на github.com, не тестом.

**Человек смотрит план — независимо от уровня `risk.sh`.** В задаче записано
«правка `.github/workflows/**` — обвязка контроля: уровень high, человек
смотрит план». По `scripts/risk.json` новый файл workflow в `harness_control`
не попадает (там только `deleted_paths` для `gitleaks.yml` и `removed_lines`),
поэтому уровень даст скрипт, а просмотр плана человеком сохраняется по слову
задачи.

**Совет по плану, круг 1** — `council.sh` код 0, блокеров нет; принято
пять замечаний, все в правку плана:
- прогресс считается по списку задач майлстоуна, а не по его счётчикам
  `open_issues`/`closed_issues` — счётчик может отстать от события
  `issues: closed` (скептик, major); страховочный прогон по расписанию раз в
  сутки закрывает и закрытие PR без события `issues` (инженер, nit);
- публикация проверяется до мерджа: триггер `pull_request` запускает publish с
  `--dry-run` на реальном runner — версия git, orphan-worktree, чтение токеном
  с `contents: write`, `git push --dry-run` (скептик, major);
- identity коммита задаёт сам сценарий, тест — без глобального git config
  (скептик, nit); расчёт контраста из теста убран (прагматик, nit);
- что значит «версии actions закреплены» — записать в план явно, на просмотр
  человеку.
Отброшены сводкой три nit прагматика без `evidence`.

**Совет по плану, круг 2** — `council.sh` код 0, блокеров нет, хеш набора тот
же. Принято:
- запрос майлстоунов — с `state=all`: без него закрытый по завершении этап
  пропадает с картинки (инженер и скептик, major, независимо); сверено грепом —
  `state=all` в плане стоял только у запроса задач. Тест «семь этапов» получил
  закрытый майлстоун со 100 %, тест формы workflow — проверку `state=all`;
- «Что не входит»: GitHub отключает `schedule` после 60 дней без активности
  (скептик, nit).
Не принято:
- исключение dependabot в `if:` (скептик, nit) — dependabot в репозитории не
  подключён, в `.github/` его конфигурации нет;
- убрать dry-run в PR (прагматик, nit) — он закрывает major круга 1 и
  единственный до мерджа проверяет чтение токеном с `contents: write`;
- слить тесты отрисовки (прагматик, nit) — вкусовое, решит реализация.
Правку круга 2 сверил оркестратор (`jq` по `approach.summary`, `plan.sh
validate` зелёный); третий круг не собирался: блокеров нет, правка буквальная,
а круг 3 исчерпал бы общий предел 5 при двух кругах ревью диффа.

**Просмотр плана владельцем (2026-10-11).** Вопросы и ответы:
- «Версии actions закреплены» — мажорным тегом, как в соседних workflow? —
  «ок»: тег, без SHA.
- Одна SVG с нейтральной палитрой (контраст 4,35:1) или две по теме? —
  «давай отдельные svg»: светлая и тёмная картинки за `<picture>`; это решение
  владельца поверх «рисует одну SVG-картинку» в теле задачи. В README
  по-прежнему одна картинка — элемент `<picture>` с двумя вариантами.
- Фраза «Этап 0 из 6 — каркас» в «Статусе» — оставить? — «убираем»: уходит
  весь первый абзац раздела (фраза и описание каркаса), он устаревает так же,
  как процент; строка про milestones и issues остаётся.
План правит шаг плана; совет по правке не собирается — развилку снял
владелец, а третий круг исчерпал бы общий предел 5 при двух кругах ревью
диффа. Правку сверяет оркестратор, ревью диффа проверит реализацию.
Сверено (`4b8ccc0`): `plan.sh validate` зелёный, `risk.sh plan` — medium,
`state=all` у майлстоунов на месте, «выносится человеку» не осталось, границы
— те же пять файлов. Пробный `gh api markdown`: `<a>` вокруг `<picture>`
санитайзер оставляет, адреса raw без camo.
