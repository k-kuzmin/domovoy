## Решения

**Триаж.** `ready: false` с одним вопросом: чем проверять живой эффект
`scripts/board.sh` на доске. Ответ владельца (2026-10-15): тест с подменённым
`gh` плюс живой прогон на карточке #159 — `In progress` после ветки, `Review`
после открытия PR, чтение через `gh project item-list`. С ответом задача
пригодна. Пункт «таблица синхронизации и `docs/pipeline.md`, если касается» —
решение о касании фиксируется в плане. Триаж назвал частичную отмену записи
0026: новая запись 0032 поверх неё, 0026 не правится.

**Объём и механизм.** Вопросы владельцу и ответы (2026-10-15): полный цикл
статусов — `In progress` (ветка задачи), `Review` (PR открыт), `Done`
(`merge-wait.sh` вернул `MERGED`), независимо от встроенных автоматизаций
доски; механизм — сценарий `scripts/board.sh <N> <статус>` с тестом и по
строке вызова в шагах `.claude/CLAUDE.md`.

**Разовое приведение доски (до задачи, 2026-10-15).** На доску добавлены
задачи после #56, закрытые переведены в `Done`, #12 — в `In progress`;
созданы представления «Доска» и «Этап 0»…«Этап 6». Встроенные автоматизации
доски API не включает — их включает владелец в интерфейсе.

## Отвергнуто

- Отдельный проект на каждый мейлстоун — карточки стояли бы в `Backlog` так
  же; этап — фильтр представления в одном проекте.
- Пауза и повторная установка статуса в `board.sh` против гонки с
  автоматизацией доски — решение владельца: гонка снимается настройкой
  доски, а перезапись позже окна паузой всё равно не ловится.
- Только строки `gh project item-edit` в `.claude/CLAUDE.md` без сценария —
  id поля и опций зашиты в текст, вызов длинный (выбор владельца).
