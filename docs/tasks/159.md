## Решения

**Триаж.** `ready: false` с одним вопросом: чем проверять живой эффект
`scripts/board.sh` на доске. Ответ владельца (2026-10-15): тест с подменённым
`gh` плюс живой прогон на карточке #159 — `In progress` после ветки, `Review`
после открытия PR, чтение через `gh project item-list`. С ответом задача
пригодна. Пункт «таблица синхронизации и `docs/pipeline.md`, если касается» —
решение о касании фиксируется в плане. Триаж назвал частичную отмену записи
0026: новая запись 0032 поверх неё, 0026 не правится.

**Объём и механизм.** Вопросы владельцу и ответы (2026-10-15): полный цикл
статусов — `In progress` (ветка задачи), `Review` (PR открыт), `Done`
(`merge-wait.sh` вернул `MERGED`), независимо от встроенных автоматизаций
доски; механизм — сценарий `scripts/board.sh <N> <статус>` с тестом и по
строке вызова в шагах `.claude/CLAUDE.md`.

**Разовое приведение доски (до задачи, 2026-10-15).** На доску добавлены
задачи после #56, закрытые переведены в `Done`, #12 — в `In progress`;
созданы представления «Доска» и «Этап 0»…«Этап 6». Встроенные автоматизации
доски API не включает — их включает владелец в интерфейсе.

## Отвергнуто

- Отдельный проект на каждый мейлстоун — карточки стояли бы в `Backlog` так
  же; этап — фильтр представления в одном проекте.
- Пауза и повторная установка статуса в `board.sh` против гонки с
  автоматизацией доски — решение владельца: гонка снимается настройкой
  доски, а перезапись позже окна паузой всё равно не ловится.
- Только строки `gh project item-edit` в `.claude/CLAUDE.md` без сценария —
  id поля и опций зашиты в текст, вызов длинный (выбор владельца).

## Шаги

- Задача заведена по явной просьбе владельца.
- Воспроизведение пропущено: задача не баг.
- Совет по плану — по маршруту (medium): скептик + инженер + страж. Признаки
  совета: правка обвязки, новая функциональность; общий механизм и
  глобальный переключатель — нет (`grep board.sh` по дереву до задачи пуст).
- Расхождение, найденное шагом плана: `tz-pipeline/TZ-pipeline.md:272`
  («статус двигает workflow по событиям …, не агент»). ТЗ продукта
  (`tz-home-agent.md`) доску не описывает; workflow-синхронизацию убрала
  ещё 0026. Ответ владельца (2026-10-15): ТЗ обвязки правит он сам,
  расхождение фиксирует запись 0032 со ссылкой на строку ТЗ.
- Совет по плану, круг 1: страж и инженер — `no_objections`, скептик —
  `another_round`; `council.sh` — код 0, блокеров нет, 3 major + 2 nit.
  Major об имени опции снят фактом: опции Status — Backlog, Ready,
  In progress, Review, Done (`gh project field-list`, 2026-10-15). Остальное —
  исправление плана шагом `step-plan`.
- Развилка после исправления (вопрос владельцу, 2026-10-15): гонку с
  встроенными автоматизациями шаг закрыл паузой 10 с и повторной
  установкой. Владелец выбрал развязку настройкой доски — совместимая
  настройка в 0032, сценарий ставит статус и один раз читает его обратно.
  Живой прогон — на карточке #159 без удаления.
- Совет по плану, круг 2: все три — `no_objections`; `council.sh` — код 0,
  3 nit. Переданы реализации: расхождение с буквой issue для `Done` назвать
  в 0032; ссылаться на раздел «Git», а не на номер строки; живой прогон
  повторить несколько раз (ложный код 1 от задержки чтения).
- Реализация — `step-implement` (порог делегирования превышен: ~450 строк),
  срезы `script` → `docs` последовательно. Отступление от
  `docs/rules/implement.md`, «Склейка срезов» («Каждый срез исполняет
  отдельный `step-implement` с `isolation: "worktree"`»): оба среза — одним
  исполнителем прямо в worktree задачи. Причина: `docs` стоит после
  `script`, параллелить нечего, а отдельные worktree добавили бы только
  перенос коммитов.

**Расхождения реализации с планом** (по отчёту исполнителя): объём больше
оценки — сценарий ~280 строк против ~150, тесты ~480 против ~280 (шапки и
пять запросов GraphQL heredoc'ами), состав файлов тот же; сверх таблицы
тестов — случай «чтение отдало пустой статус → код 1»; автоматизация
названа по интерфейсу — «Pull request merged». Ответ доски разбирается
построчно, а не `read` с IFS=TAB, как в старом сценарии: при пустом первом
поле значения сдвигаются.

**`Done` — отступление от буквы issue.** Сбой `board.sh` на `In progress` и
`Review` пишется строкой в журнал; сбой на `Done` — сообщением человеку в
сессии: после мерджа журнал уже в `main`, а `.claude/CLAUDE.md`, раздел
«Git», отдельных коммитов после мерджа не допускает.
