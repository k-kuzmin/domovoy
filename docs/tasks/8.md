**Гонка postgres — исправлена в первопричине (2026-10-12).** Шаг починки
поймал в полном прогоне `pg_restore: … the database system is shutting down`
после `postgres Healthy`. Причина — healthcheck postgres в
`docker-compose.yml`: `pg_isready` без `-h` ходит через сокет и зеленеет на
временном сервере инициализации `docker-entrypoint.sh`
(`listen_addresses=''`). Опыт, плотный опрос в контейнере `postgres:16-alpine`
при первой инициализации: сокет `ok`/TCP `no` — 29 замеров, затем оба `no`
(остановка временного сервера), затем оба `ok`. Healthcheck переведён на
`pg_isready -h 127.0.0.1` (75b21e2). Тот же healthcheck гейтит
`depends_on: service_healthy` у api — гонка снята и для него. Правка
`docker-compose.yml` в плане не заявлена — расхождение, записано здесь.

**Решения владельца по резюме (2026-10-12).**
- Найденное во круге 2 (M2 порча архива, остатки временной базы, проверка

  памяти, для записи нового бэка удалять самые старые, если выходим за рамки
  лимита». `backup.sh --max-size <ГБ>`: до записи нового — удаление
  старейших `domovoy-backup-*`, пока сумма с оценкой нового (размер
  последнего) не влезет; последний успешный не удаляется никогда; не влезает
  или мало места на носителе — отказ с сообщением; `--keep` остаётся.
- Пустая схема Backend: `restore.sh` при 0 таблиц печатает явную строку

  фиксируется, что пункт «Backend видит свои данные» на живом стеке подтверждён
  тестом с маркером, а живой — с первой миграцией.
- Полный `backup.test.sh` — только работой CI `backup` на PR; положительную
  ветку HA API на текущем коде первым исполнит прогон владельца
  `restore.sh --check`.

**Починка по кругу 2 (2026-10-12).** Коммиты c539e36..f760ee2: архив читает
обычный файл один раз (`gettarinfo(fileobj=…)`), ссылки на каталоги — в
архиве ссылкой, исчезнувший каталог — пропуск; `restore.sh:103` `|| true`;
остатки временных баз — удаляются по точной форме имени
`^domovoy_backup_verify_[0-9]{8}t[0-9]{6}z$`, `dropdb` без `--force`;
`--max-size` по решению владельца — отказ до удаления, если с оценкой не
влезает даже последний бэкап (безопаснее буквального «удалить до последнего,
потом отказать»); без `--max-size` свободное место не проверяется — пример
`schtasks` в README идёт с `--max-size`; пустая схема — явная строка.

**Ревью корректности, круг 3 (2026-10-12).** Blocker: ссылка с абсолютной

параллельном прогоне уточнён (2941e88). Major «журнал отстаёт» — этой
записью. Починку сверил оркестратор по диффу и тестам, нового круга нет.

ссылку, лежащую в архиве позже, — проверка при снятии и распаковка могут
