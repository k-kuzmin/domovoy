## Решения

**Триаж (2026-11-10).** `ready`, вопросов владельцу нет. Способ проверки по
пунктам критерия: привязка — живой прогон на стенде (`curl` на порт стенда);
провал миграции и порядок postgres healthy → migrate → api → `/health` —
сценарии `scripts/stand.test.sh` с подменённым движком; отсутствие образа
migrate после `down` — сверка `image ls` с базовым снимком; описание —
правка `docs/rules/implement.md`. Для плана: исключение «миграция к базе
стенда — не команда человека» в `main` ещё не записано ни в
`docs/rules/implement.md` (строка 308), ни в `.claude/CLAUDE.md`, «Команды
человека»; нужна ли правка `.claude/CLAUDE.md` той же задачей — решение плана.

**План.** Сервис `migrate` (стадия `migrate` Dockerfile api) в
`deploy/stand/docker-compose.stand.yml` под профилем; `up` собирает api и
migrate, запускает `run --rm migrate` после здоровых postgres и HA, до
подъёма стека; провал — `fail_up` со сносом. `.claude/CLAUDE.md` правится
одной оговоркой в «Команды человека» со ссылкой на `docs/rules/implement.md`:
без неё норма дословно противоречит поведению `up`. Развилки нет;
исполнитель — субагент (~150–200 строк, 5 файлов).

**Код привязки.** Критерий issue ждёт 200 от
`POST /api/v1/admin/pairing-codes`, контракт отдаёт 201
(`src/Domovoy.Api/Endpoints/AdminEndpoints.cs:51`). Владелец 2026-11-10:
поправить критерий, а не код API — тело issue исправлено на «201 Created».

**Совет по плану, круг 1.** Скептик, инженер, страж; `council.sh` — код 0,
блокеров нет. Два major про код 201 закрыты ответом владельца выше. Major
скептика (подделка compose не доказывает поведение `run --rm migrate` и
`down --rmi local` на настоящем compose) и два nit (`-d "$POSTGRES_DB"` в
`status`, квотирование `sh -c`) исправляет шаг плана. Второй круг не нужен:
блокеров не было.

**Исправление по кругу 1.** Образ migrate собирается явной командой
`buildx build --target migrate` строителем стенда; сервис migrate в надстройке
стенда — той же формы, что боевой: только `image:` и `pull_policy: never`, без
`build`, так что `run --rm --pull never migrate` пересобрать его не может;
`down` удаляет образ явно `image rm`, а не полагается на `--rmi local`. SQL
`status` уходит в `psql` через stdin с `-d "$POSTGRES_DB"`.

**Просмотр плана владельцем (2026-11-10).** План согласован как есть,
включая оговорку в `.claude/CLAUDE.md`.

**Коммиты шагов.** Субагент в worktree-сессии не может добавить gitleaks в
PATH для `git commit` (изоляция worktree отбивает и `export`, и
`powershell -Command` рядом с git) — коммитит оркестратор.

**Реализация.** Срез stand — `step-implement` прямо в worktree задачи, без
отдельного worktree среза: срез docs зависит от stand и мал (~10 строк),
его сделал оркестратор после переноса. Расхождение с планом: шесть
существующих сценариев `stand.test.sh` прямо противоречили новому
поведению (`image rm` образа migrate в `down`, `image:` у migrate, `exec` в
postgres в `status`); их утверждения сужены до прежнего смысла — хелпер
`other_image_rm` исключает только строку `image rm domovoy-stand-<N>-migrate`,
запрет `image:` — только в блоке api, запрет `cp|exec` — только в HA.
Сверх плана: сценарий неудачного `image rm` в `down`; SQL статуса —
`to_regclass('"__EFMigrationsHistory"')` по search_path (в Data
`HasDefaultSchema` не задан).

**Ревью диффа, круг 1 (medium).** Корректность — changes_requested без
блокеров: major — «тот же образ, что у боевой выкатки» в
`docs/rules/implement.md` и шапке `stand.sh` неверно (общие стадия и путь
запуска, образ — из исходников ветки), nit — комментарий про `image rm` без
`-f`, nit — стадия в шапке журнала; все три исправлены текстом, поведение не
менялось. Безопасность — approve. Совет по диффу (скептик, инженер, страж) —
`council.sh` код 0; два nit скептика сводка отбросила (строки вне изменённых
участков), их суть — живой прогон `run --pull never` и «миграций 0» при
пустой истории; второе невозможно: миграция идёт одной транзакцией
`--single-transaction`. Второго круга нет: блокеров не было.

## Шаги

- Воспроизведение пропущено: задача не баг (feature).
- Совет по плану: признаки — правка обвязки, миграция, общий механизм

  диффа: `docs/rules/implement.md` запрещает запуск изменённого `stand.sh` до
  ревью.
