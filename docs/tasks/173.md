## Решения

**Триаж (2026-11-10).** `ready`, вопросов владельцу нет. Способ проверки по
пунктам критерия: привязка — живой прогон на стенде (`curl` на порт стенда);
провал миграции и порядок postgres healthy → migrate → api → `/health` —
сценарии `scripts/stand.test.sh` с подменённым движком; отсутствие образа
migrate после `down` — сверка `image ls` с базовым снимком; описание —
правка `docs/rules/implement.md`. Для плана: исключение «миграция к базе
стенда — не команда человека» в `main` ещё не записано ни в
`docs/rules/implement.md` (строка 308), ни в `.claude/CLAUDE.md`, «Команды
человека»; нужна ли правка `.claude/CLAUDE.md` той же задачей — решение плана.

**План.** Сервис `migrate` (стадия `migrate` Dockerfile api) в
`deploy/stand/docker-compose.stand.yml` под профилем; `up` собирает api и
migrate, запускает `run --rm migrate` после здоровых postgres и HA, до
подъёма стека; провал — `fail_up` со сносом. `.claude/CLAUDE.md` правится
одной оговоркой в «Команды человека» со ссылкой на `docs/rules/implement.md`:
без неё норма дословно противоречит поведению `up`. Развилки нет;
исполнитель — субагент (~150–200 строк, 5 файлов).

**Код привязки.** Критерий issue ждёт 200 от
`POST /api/v1/admin/pairing-codes`, контракт отдаёт 201
(`src/Domovoy.Api/Endpoints/AdminEndpoints.cs:51`). План ждёт 201; вопрос
владельцу — поправить формулировку критерия, а не код API.
