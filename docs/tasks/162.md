## Решения

**Триаж (2026-10-16).** Вердикт — «не готова». Пункт 3 `docs/rules/triage.md`
(объём) не пройден: в задаче шесть поставок (образ в GHCR, каталог
развёртывания, `update.ps1` с бэкапом, миграциями, синхронизацией `.env` и
откатом, WSL-настройки `engine-setup.ps1`, очистка образов, README) — больше
порога `size` в `scripts/risk.json` (11 файлов, 1538 строк). Способ проверки не
назван явно у пунктов критерия про миграцию с бэкапом, синхронизацию `.env` и
отказ при неработающем движке — их назначает план (контракт приёмки); пункты
про миграцию и чистую машину требуют среды — стенд #164 и владелец.
Расхождение для плана: перенос стека с `/mnt/<диск>` в файловую систему
дистрибутива расходится с записью 0028 («Клон там виден как `/mnt/<диск>/…`»)
— нужна новая запись в `docs/decisions/`.

**Объём (2026-10-16).** Вопрос владельцу: разбить задачу и с чего начать.
Ответ: «Не разбивать» — вся задача одним PR.

**Указание владельца (2026-10-16).** «В целом действуй по своим
рекомендациям»: развилки решает оркестратор по своей рекомендации и пишет
сюда. Живые проверки (миграция с бэкапом, откат с плохим образом,
синхронизация `.env`, отказ при неработающем движке) — на тестовом стенде
#164, не на боевом стеке.

**План.** Подробно — [`162.plan.json`](162.plan.json). SQL миграций —
`dotnet ef migrations script --idempotent` в образе `migrate`, применяется
psql; стек — отдельный клон `/srv/domovoy` в `domovoy-engine`; логика
обновления — `deploy/update.sh`, обёртка `deploy/windows/update.ps1`; запись
0034 частично заменяет 0028.

**Развилка: откат по чему.** Откат образа — только по провалу `up --wait` и
`/health`; красный `engine-setup.ps1 -Check` — код 5 без отката. Выбрал
оркестратор по рекомендации плана (указание владельца выше): звенья хоста
(firewall, portproxy, задачи) от образа не зависят, и откат рабочего образа
из-за настройки хоста ничего не чинит. Прагматик совета согласен.

**Совет по плану, круг 1.** Код 0, блокеров нет. Приняты все замечания:
тег нового коммита задаётся до `pull` и `migrate` (инженер); состояние
отката хранится на диске и переживает обрыв процесса (скептик); постоянная
сквозная проверка в ci-heavy убрана — один живой прогон на стенде с записью
сюда (прагматик); один Windows-тест обёртки вместо двух; сборка стадии
`migrations` — первым шагом реализации.
