## Решения

**Триаж (2026-10-12).** Вердикт `ready: false`, два вопроса. Пути и ссылки на
ТЗ (5.1.2, 5.1.3, REPO-4) существуют, противоречия с правилами проекта нет.

- Вопрос триажа «где наблюдать статус „не сконфигурировано“ без токена» снят
  оркестратором по коду, владельцу не задавался: незаполненный секрет даёт
  `ComponentState.NotConfigured` → `HealthStatus.Degraded`
  (`src/Domovoy.Api/Health/ComponentsHealthCheck.cs:73`), анонимный `/health`
  отдаёт его как `{"status":"degraded"}`, а отказ — как `unhealthy`. Способ
  проверки — `curl -s` анонимного `/health` на чистом окружении.
- Объём: оценка 6–10 ч при правиле «больше 8 ч — дробить». Владелец
  (2026-10-12): вести **одним PR**. Если прогон на чистом окружении вскроет
  больше расхождений, чем укладывается в PR, — разбиение предлагается тогда.

**Живые прогоны делает владелец.** Агенту создание `.env` закрыто правами, даже
во временном клоне; прогон во втором клоне на хосте отвергнут — совпали бы
имя проекта, порт и том рабочего стека. Чистая машина — одноразовый
контейнер `docker:dind` со своим демоном; сценарий прогона читает
оркестратор, запускает владелец через `!`.

**Совет по плану, круг 1 (2026-10-12).** Скептик, инженер, страж — все
`no_objections`, блокеров нет, четыре nit приняты и внесены в план:
доказательство подъёма — `--wait` и `compose ps --format json`, а не grep
выравнивания лога; README про 401 — «на этапе каркаса»; `RestartCount`
сверяется пятью прогонами до PR; PR не открывается без вывода прогона 2 в
«Проверено».

**Порт API на хосте: 8080 → 18080 (2026-10-12).** Владелец: «порт 8080 надо в
целом освободить. его использует мсп для unity движка». На хосте 8080 делят
Docker Desktop (`0.0.0.0`) и `wslrelay` (`[::1]`) — `curl localhost:8080` может
уйти по IPv6 не в стек. Владелец выбрал 18080 и сделать это в #5, а не
отдельной задачей. Порт внутри контейнера остаётся 8080. План расширен.

**Совет по плану, круг 2 (2026-10-12).** Страж и инженер — `no_objections`,
скептик — `another_round` (2 major, 1 nit); `council.sh` — код 0, блокеров
нет. Все три замечания сняты проверкой, план не менялся:
- «чистый `docker:dind` не достанет образы из сети владельца» — прогон 1
  скачал `docker:dind`, базовые образы и пакеты NuGet, образ api собран;
- «`RestartCount = 0` недетерминирован из-за гонки со стартом postgres» —
  api стартует после `condition: service_healthy` postgres
  (`docker-compose.yml:58-60`);
- «18080 в исключённом диапазоне Hyper-V/WinNAT» — `netsh int ipv4 show
  excludedportrange protocol=tcp` на хосте: 18080 ни в одном диапазоне.

  уже отличает «не сконфигурировано» от отказа.

  проекта.

- Смена порта внутри контейнера — конфликт только на хосте, healthcheck
  контейнера ходит изнутри.
