## Решения

**Якорь таблицы — строка заголовка `| Эндпоинт | Зачем | Запись |`, а не фраза
«Анонимные эндпоинты сейчас».** Это расхождение с планом, взятое из nit 1 ревью
плана круга 2: фраза стоит в абзаце с жёстким переносом, и переформулировка
разорвала бы её. Строка заголовка после отбрасывания отступа в файле одна.
Её же называет сообщение «таблица правила 7 не найдена».

**Эндпоинт без метода сопоставляется со строкой таблицы по пути.** Так
регистрирует `/health` `MapHealthChecks`: без `HttpMethodMetadata`, эндпоинт
отвечает на любой метод. Таблица при этом называет GET, и это расхождение
сверка не ловит. Правило записано в комментарии к `Reconcile` и закреплено
тестами `MethodlessEndpointMatchesRowByPath` и `MethodlessUndocumentedEndpointIsReported`.

**Красные прогоны — временными правками `ApiV1Endpoints.cs`, а не строкой в
таблице.** Опора — `.claude/CLAUDE.md`, «Границы работы агента → Файлы,
которые агент не трогает»: «Изменение любого из них требует апрува человека»
(nit 2 ревью плана круга 2). Это касается и временной правки.

**Строка таблицы, первая ячейка которой не разбирается как `МЕТОД /путь`, —
ошибка разбора, а не пропуск.** Иначе строка, записанная не по форме, молча выпала бы
из сверки.

## Починка: разделитель таблицы

Построчное замечание Copilot, id 4087334580 от 2026-09-23T21:09:00Z,
`tests/Domovoy.Tests/AnonymousEndpointsRuleTests.cs:220-223`. Решение
владельца на PR: принять, чинить в этом PR.

**Причина.** `ParseTable` начинал данные с `header + 2`, считая строку
`header + 1` разделителем и не проверяя её. Удалённый разделитель превращал
первую строку данных в пропущенную: при двух и более строках сверка
оставалась зелёной без неё — лишний или недостающий анонимный эндпоинт в
этой строке не был бы замечен.

**Сделано.** Строка за заголовком проверяется регуляркой разделителя
(`|`, `-`, `:`, пробелы и табуляция; в каждой ячейке хотя бы один `-`);
отсутствие или порча — `InvalidOperationException` с якорем таблицы и
словами «нет строки-разделителя». Заголовок последней строкой документа —
тот же отказ, а не выход за массив.

| Прогон | Исход |
|---|---|
| новые случаи `MissingSeparatorIsReported` (без разделителя, испорченный `-x-`, заголовок без продолжения) до правки | не пройдено 3 из 13 в классе: первый — исключения нет (первая строка пропущена молча), два других — другое сообщение |
| после правки: `dotnet build --no-restore -c Release` | предупреждений 0, ошибок 0 |
| `dotnet test --no-build -c Release` | пройдено 55, не пройдено 0, пропущено 0 |
| `dotnet format --verify-no-changes --no-restore` | замечаний нет |
| `bash scripts/test-count-invariant.sh` | до правки снимка «55 против 51», после — сходится; снимок 51 → 55 |

Положительный случай `AlignedSeparatorIsAccepted` (`| :--- | :---: | ---: |`)
закрепляет, что регулярка не отказывает разделителю с выравниванием.
