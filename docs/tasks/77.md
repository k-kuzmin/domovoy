| Вопрос | Ответ | Кто ответил |
|---|---|---|

## Решения

**Наблюдение снимается со стенограмм субагентов, а не с их отчётов.**
Субагент, докладывающий «я haiku» или «меня отбил хук», — это то самое
утверждение автора о собственной работе, ради замены которого задача и
заведена. Стенограммы лежат в
`~/.claude/projects/<проект>/<сессия>/subagents/agent-<id>.jsonl`, рядом
`agent-<id>.meta.json` с полем `agentType`. Отсюда берутся тип шага и модель.

**Проба границы сделана командой только на чтение.** `dotnet ef migrations
list`, а не `database update` или `drop`: если бы хук не подхватился, ценой
ошибки был бы вывод списка, а не изменение схемы.

**В пробе был положительный контроль.** Отказ без единой прошедшей команды
неотличим от сломанного хука: `scripts/step-bash-allow.sh` отказывает во всём
и когда не найден `jq`. Поэтому первым вызовом шёл разрешённый `git status`, а
`jq --version` проверен до прогона.

## Что наблюдалось

### Пункт 1 — определение становится вызываемым типом шага

Вызовы `step-triage` и `step-implement` приняты и породили субагентов.
Свидетельство — файлы `meta.json` рядом со стенограммами:

```
{"agentType":"step-implement","description":"Проба границы команд","spawnDepth":1}
{"agentType":"step-triage","description":"Триаж задачи 77","spawnDepth":1}
```

Подхватываются. В сессии #70 тип `step-review-correctness` не находился —
разница в том, что определения тогда появились посреди сессии, а `.claude/agents/`
читается при её старте.

### Пункт 2 — `model` из frontmatter применяется

```
jq -r 'select(.type=="assistant") | .message.model' agent-<id>.jsonl | sort | uniq -c
```

| Субагент | `model` в определении | Что в стенограмме |
|---|---|---|
| `step-triage`, замер 1 | `haiku` | 34 × `claude-haiku-4-5-20251001` |
| `step-triage`, замер 2 | `haiku` | 31 × `claude-haiku-4-5-20251001` |
| `step-implement` | поля нет | 10 × `claude-opus-5` |

Модель оркестратора в той же сессии — `claude-opus-5`. То есть подтверждены
обе половины утверждения из `.claude/CLAUDE.md`: где модель названа, идёт она;
где не названа, идёт модель сессии, а не что-то третье.

### Пункт 3 — `hooks.PreToolUse` отбивает команду вне списка

Проба на `step-implement`, четыре вызова Bash, каждый ровно один раз.

| Вызов | Результат |
|---|---|
| `git status` | выполнился — положительный контроль |
| `dotnet ef migrations list` | отказ |
| `git status && dotnet ef migrations list` | отказ на втором сегменте, вывода первого не пришло |
| `gh issue view 77 --output json` | отказ по флагу |

Дословно, вызовы 2 и 3:

```
Команда «dotnet ef migrations list» не входит в список разрешённого на этом
шаге. Разрешено: dotnet restore dotnet build … bash scripts/step-bash-allow.test.sh.
```

Дословно, вызов 4:

```
Флаг --output запрещён у git и gh: «gh issue view 77 --output json».
Он делает из читающей команды запись в файл, минуя набор инструментов.
```

Второе, независимое наблюдение — на другом определении, с другим списком:
`step-triage` (`gh issue view`, `grep`, `head`, `tail`) получил за три прогона

```
Команда «cd <путь к репозиторию>» не входит в список разрешённого…
Команда «pwd» не входит в список разрешённого…
Команда «gh api repos/…/issues/77 --jq '.body'» не входит в список разрешённого…
Перенаправление вывода запрещено на шаге: «gh issue view 77 --comments 2>&1 | head -100»
```

Это существеннее повторной пробы на том же файле: списки разные, отказы разные,
значит подхватывается аргумент хука из конкретного определения, а не что-то
общее.

Отказ пришёл именно по списку, а не по поломке: в стенограммах строка
`не найден jq` не встречается ни разу, `jq --version` — `jq-1.8.1`.

**Причина отказа доходит до субагента текстом и шаг не роняет.** Доставляется
она каналом ошибки инструмента — тело обёрнуто в `<error>…</error>`, — а не
выводом команды. Оба субагента после отказа продолжили работу.

## Найдено попутно — определение триажа не помещается в собственные рамки

Первый замер триажа кончился без вердикта: 17 вызовов инструментов при
`maxTurns: 15`. Из 15 вызовов Bash три отбиты границей (`cd`, `pwd`, `2>&1`),
ещё три — повторы `gh issue view 77`. Второй замер вердикт дал, потому что
читал файлы через `Read` и `Glob`, а не через `head` в Bash: те же семь
вызовов Bash, но одиннадцать оставшихся ходов ушли на чтение инструментами.

Разница между «дошёл» и «не дошёл» здесь — случай, а не устройство шага.
Правила шага велят прочитать `docs/rules/triage.md` и `docs/rules/reading.md`
целиком, а в списке команд нет ни `cd`, ни `pwd`, ни `2>&1`, и потолок — 15.
Это не отказ механизма — механизм как раз сработал, — а слишком узкая рамка.
Заведена issue #78; правки определений в объём #77 не входят.
