## Решения

**Триаж (2026-11-11).** Вердикт `step-triage` — не готова, два вопроса
владельцу. Выводы сверены по коду оркестратором:

- раздельные статусы БД, HA, HA WebSocket и LLM в `main` уже отдаёт
  `GET /api/v1/health` (`src/Domovoy.Api/Endpoints/HealthEndpoints.cs`),
  анонимный `/health` — одно слово по записи
  [0002](../decisions/0002-split-health-endpoint.md);
- `LlmProbe` различает 403 (`RejectedByGeography`) и сетевую ошибку
  (`Unreachable`, «сетевая ошибка»), тестов на эти ветки нет;
- «не сконфигурировано» при пустых секретах уже покрыто тестом
  `UnfilledSecretsYieldNotConfigured`;
- `request_id` в `LogContext` никто не кладёт: он есть только в двух
  предупреждениях `ChatEndpoints.cs`. Комментарий о корреляции в
  `Program.cs` — описание, а не поведение;
- пункт «нет секретов в логах старта» проверяется grep по значениям из
  `.env`, который агенту закрыт: прогон — владелец или стенд.

Ответы владельца (2026-11-11):

1. Эндпоинт раздельных статусов — `GET /api/v1/health`, как в 0002 и #9;
   `/health` в критерии — неточность формулировки, анонимный `/health` не
   меняется.
2. Одна задача, без разбиения: остаток — корреляция `request_id` с протяжкой
   до вызова HA и тесты пробы LLM.

## Отвергнуто

- Раздельные статусы в анонимном `/health` — противоречит записи 0002
  (состав компонентов — разведданные для постороннего); владелец выбрал
  `/api/v1/health`.
- Разбиение на две задачи — после вычета сделанного в `main` остаток
  укладывается в один PR.
