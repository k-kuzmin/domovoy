## Решения

**Первый заход остановился до первой правки защищённого пути** — метки
`agent/allow-protected` на задаче не было. Второй заход начат после того, как
её поставил человек.

**Замер 125-5 «до правки»** — `bash scripts/risk-score.test.sh` на `d0bf9d7`,
stdout и stderr вместе, отбор по `No such file|Размер диффа|провалено|FAIL`:

```
scripts/risk-score.test.sh: line 900: /tmp/tmp.BimkZFEnrq/repo-27/src/Domovoy.Core/Bulk.cs: No such file or directory
[ ok  ] Размер диффа выше порога даёт medium, а на строку ниже порога сигнала нет
Пройдено: 46, провалено: 0, пропущено: 0
```

Строк «No such file or directory» — одна, про `Bulk.cs`.

**Ветка пачки заведена от `main` заходом #125, а не #75.** На момент захода
ветки не было ни локально, ни PR по ней; план #75 не согласован. Порядок
пачки (#75 первой) поэтому не соблюдён в части «кто завёл ветку»; файлы #75 и
#125 не пересекаются (риск 7 плана).

**125-3-seen-red: красный прогон до правки гейта.** Сценарии проверки 11
добавлены в `scripts/guard.test.sh`, `scripts/guard.sh` ещё не тронут:

```
[ FAIL] проверка 11: каждый из четырёх вызовов снятия ограничений схемы без метки — гейт падает и называет вызов
[ FAIL] проверка 11: снятие ограничений схемы с меткой agent/allow-destructive-migration — гейт пропускает
[ ok  ] проверка 11: создание индекса, внешнего и уникального ключа — гейт молчит
Сценариев пройдено: 57, провалено: 2, пропущено: 0
```

Причины — `код возврата 0, ожидался 1` и `в выводе нет: Проверка 11: …` по
каждому из четырёх имён. Отрицательный сценарий до правки зелёный — так и
должно быть: проверки ещё нет, шуметь нечему.

**Три нейтрализации — после коммита `08da574`.** Реализация закоммичена до
нейтрализаций, иначе критерий «после возврата `git diff --stat --
scripts/guard.sh` пуст» невыполним: дифф показал бы саму проверку 11. Возврат —
`git checkout -- scripts/guard.sh`: команда в списке шага есть, план исходил из
обратного и предлагал обратную правку. После каждого возврата `git diff --stat
-- scripts/guard.sh` пуст.

- (а) `select_lines` проверки 11 заменён на `: > "$CONSTRAINT_DROP_HIT"`:

  ```
  [ FAIL] проверка 11: каждый из четырёх вызовов снятия ограничений схемы без метки — гейт падает и называет вызов
  [ FAIL] проверка 11: снятие ограничений схемы с меткой agent/allow-destructive-migration — гейт пропускает
  Сценариев пройдено: 57, провалено: 2, пропущено: 0
  ```
- (б) шаблон сужен до `(Index|ForeignKey|UniqueConstraint|PrimaryKey)`.
  Краснеет и соседний сценарий проверки 4 — на `table.PrimaryKey`:

  ```
  [ FAIL] проверка 4: первичный ключ внутри CreateTable и HasKey снимка модели — гейт молчит
  [ FAIL] проверка 11: создание индекса, внешнего и уникального ключа — гейт молчит
  Сценариев пройдено: 57, провалено: 2, пропущено: 0
  ```
- (в) проверка 11 включена, четыре имени дописаны в `DESTRUCTIVE_RE`. В каждом
  из двух сценариев по четыре строки, по одной на имя:

  ```
          ! в выводе есть лишнее: Проверка 4
  [ FAIL] проверка 11: каждый из четырёх вызовов снятия ограничений схемы без метки — гейт падает и называет вызов
          ! в выводе есть лишнее: Проверка 4
  [ FAIL] проверка 11: снятие ограничений схемы с меткой agent/allow-destructive-migration — гейт пропускает
  Сценариев пройдено: 57, провалено: 2, пропущено: 0
  ```

После возврата — `Сценариев пройдено: 59, провалено: 0, пропущено: 0`.

**Имя класса миграции в фикстурах — без `Drop`** (`RemoveIndex`, а не
`RemoveDropIndex`). Строка `public partial class RemoveDropIndex` сама совпала
бы с шаблоном проверки 11 и дала второе попадание, а `migration_line` с иглой
`DropIndex` нашла бы её, а не вызов. Игла поэтому — `migrationBuilder.<имя>(`.

**Раздел «разрешено» проверки 11 печатает `файл:строка`** — форма проверки 9,
а не `cut -f1,2` проверки 4 (там между путём и строкой табуляция). Сценарий с
меткой поэтому ждёт путь вместе с номером строки.

Замечание 1 ревью плана, круг 2: тело PR пачки обязано писать `Part of #125`
и не содержать `Closes/Fixes/Resolves #125` — проверяет оркестратор перед
снятием черновика.
