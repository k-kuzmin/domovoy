## Решения

**Триаж.** `ready: false` — у пунктов «адрес статический» и «порты на роутере
не открыты» не назван способ проверки. Вопрос владельцу: ручное наблюдение или
артефакт проверки в репозитории. Ответ владельца (2026-10-11): ручное.
Владелец смотрит в роутере резервирование адреса и отсутствие проброса портов
и пишет итог в issue без самих адресов.

**Размещение HA — сервис общего `docker-compose.yml` под профилем `ha`.**
Решение владельца (2026-10-11) из двух вариантов: отдельный compose-файл или
профиль в общем. Профиль сохраняет смысл записи 0004 — обычный
`docker compose up` на чистой машине HA не тянет, — и при этом даёт общую сеть
стека (Backend находит HA по имени сервиса из `.env.example`) и буквальное
выполнение критерия «в общем стеке». Запись 0004 частично заменяется новой
записью 0027.

**Временная площадка.** До выделенной машины стек живёт на рабочем ПК
владельца под Docker Desktop (AR-7, комментарий в #1). Сеть хоста там
недоступна, HA публикует порт на хост; сеть хоста — вопрос переезда.

**Совет по плану, круг 1 — код 2.** Инженер вернул `escalate`, скептик — три
major. Первопричина главного: вход `issue.md` оказался пустым
(`gh issue view --comments` без терминала ничего не вывел), советники сверяли
критерий по самому плану. Вход пересобран через `gh issue view --json`.
Исправлено в плане: тег образа проверен `docker manifest inspect`; тест режет
compose на блоки по отступу, игнорирует комментарии, проверяет отсутствие
профиля у postgres и api и проходит три мутации; «статический адрес» на
временной площадке — адрес хоста, резервирование в DHCP; к ручной проверке
роутера добавлена таблица UPnP; публикация на 0.0.0.0 принята явно (127.0.0.1
закрыл бы ЛВС), недоступность извне — ручная проверка, пишется в 0027; README —
`--profile ha down` и `COMPOSE_PROFILES=ha`.

**Совет по плану, круг 2 — код 0.** Владелец согласился на второй круг
(2026-10-11). Страж и инженер — без замечаний, скептик — три major и nit.
Исправлено в плане: порядок первого запуска (onboarding сразу с хоста, пока
страница создания владельца открыта ЛВС; остаточный риск — в 0027);
допустимые литералы 0.0.0.0 и 127.0.0.1 исключены из грепа A5 явно; README
предупреждает про `down -v` и `volume prune`. Трактовка A2 вынесена

**Публикация порта HA на всех интерфейсах.** Подтверждено владельцем

**Трактовка A2 подтверждена владельцем** (2026-10-11): на временной площадке

с `--build`; тест принимает только встроенную форму `profiles: ['ha']`.
`HA_HTTP_PORT` в `appsettings.json` не добавлен: это порт хоста для compose, не
настройка приложения.

## Отвергнуто

- Отдельный `docker-compose.ha.yml` — отдельная сеть Docker, Backend не видит
  HA по имени сервиса; критерий #2 «в общем стеке» пришлось бы переписывать.
- Привязка порта HA к 127.0.0.1 или адресу ЛВС — первое закрывает ЛВС, второе
  требует реального адреса в конфигурации.
- Артефакт проверки статического адреса и закрытых портов в репозитории —
  результат зависит от роутера владельца, скрипт его не наблюдает.
