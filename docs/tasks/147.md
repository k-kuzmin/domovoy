## Решения

**Триаж (2026-10-13).** Вердикт `ready: false`. Пути из задачи существуют,
ссылки на ТЗ (AR-5, NFR-OBS-1, NFR-OBS-3) есть, противоречия с правилами нет:
journald — драйвер логов движка, а NFR-OBS-1 про логи приложения. Тип задачи
`chore`, не `decision`. Вопросов было два, один снят оркестратором.

- Какие тесты входят в «тесты зелёные» — снят как вопрос: это тесты скриптов,
  которые трогает дифф, и устанавливается это по коду.
- Как проверять «шаги README для нового ПК выполнимы» и «`-Uninstall` снимает
  движок без отката» — ответ владельца 2026-10-13: **тесты + чтение**.
  `-Uninstall` проверяется сценариями `engine-setup.test.sh` (что снимается,
  тома не трогаются, отката нет), README сверяется построчно с параметрами
  скриптов. Путь `-Install` уже прогнан вживую в #6. Живого сноса и чистой ВМ
  нет.

## Отвергнуто

- Вариант A развилки HA (без healthcheck, `healthcheck=нет` в журнале
  замера) — критерий выполнялся бы только после его правки в issue; владелец
  выбрал B.
- Решение о healthcheck HA дополнением к 0028 вместо отдельной записи 0029
  (прагматик, круг 3: минус файл, план до порога) — владелец явно выбрал
  отдельную запись, зная о 0027.
- Живой прогон `-Uninstall` и проверка README на чистой ВМ — владелец выбрал
  тесты и чтение: живой снос останавливает рабочий стек, чистой машины нет.

**План (2026-10-13).** В карточке одна развилка: добавлять ли healthcheck
контейнеру `homeassistant`. Без него пункт «переход каждого контейнера в
healthy» для HA буквально невыполним. Триггер «позвать человека»: по порядку
`.claude/CLAUDE.md` сначала совет и исправление плана, потом вопрос владельцу.
Реализация — субагентом, последовательно тремя коммитами: снятие Desktop,
journald, хронология. Параллелить нельзя: все части правят `engine-setup.ps1`
и его тест.

**Совет, круг 1 (2026-10-13).** `council.sh` — код 0, блокеров нет; страж
`no_objections`, скептик и инженер `another_round`. Принято 4 major и 2 nit:
развилка HA; кодировка вывода `wsl.exe` в замере; поведение замера, пока
зонд отвечает отказом; потеря хвоста при кэшировании записи vhdx — нужен
критерий остановки живого прогона; `daemon.json` с чужими ключами; сценарии
`engine-setup.test.sh` вне CI.

**Развилка HA — ответ владельца 2026-10-13: вариант B.** Контейнеру
`homeassistant` добавляется healthcheck, критерий «переход каждого в healthy»
выполняется буквально. Вопрос задан до исправления плана: от ответа зависит
само исправление.

**Совет, круг 2 (2026-10-13).** `council.sh` — код 1. Blocker стража:
healthcheck HA противоречит записи 0027 («Healthcheck контейнера HA и
зависимость `api` от HA не заводятся»). Оркестратор, рекомендуя вариант B,
0027 не сверил — владелец выбирал без этого знания. Major скептика:
`/manifest.json` без компонента frontend отдаёт 404, проверка HA должна от
frontend не зависеть. Major инженера: перечень файлов с остатками
`Interactive` в приёмке no-desktop не совпадает с тем, что даст греп
(`ops/backup/backup.test.sh`).

**Повторный вопрос владельцу о HA — ответ 2026-10-13: healthcheck и новая
запись решения**, частично заменяющая 0027 в части healthcheck; зависимости
`api` от HA по-прежнему нет.

**Совет, круг 3 (2026-10-13).** `council.sh` — код 0. Страж и инженер
`no_objections`, blocker стража круга 2 снят самим стражем. Принято:
скептик — часовой пояс ВМ (моменты зонда однозначные: epoch или явный UTC);
итог замера не `ok`, если зонд отказал на всех опросах; nit — повторный
`container_start` при перезапуске; nit прагматика — убрать сценарий сверки
README через AST. Отвергнут major прагматика — см. «Отвергнуто».

**План владельцу (2026-10-13).** Рендер (96 тыс. символов — больше предела
комментария GitHub) показан в сессии, в issue не публиковался. Владелец
план посмотрел и дал старт реализации («приступай»).
