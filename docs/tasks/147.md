## Решения

**Триаж (2026-10-13).** Вердикт `ready: false`. Пути из задачи существуют,
ссылки на ТЗ (AR-5, NFR-OBS-1, NFR-OBS-3) есть, противоречия с правилами нет:
journald — драйвер логов движка, а NFR-OBS-1 про логи приложения. Тип задачи
`chore`, не `decision`. Вопросов было два, один снят оркестратором.

- Какие тесты входят в «тесты зелёные» — снят как вопрос: это тесты скриптов,
  которые трогает дифф, и устанавливается это по коду.
- Как проверять «шаги README для нового ПК выполнимы» и «`-Uninstall` снимает
  движок без отката» — ответ владельца 2026-10-13: **тесты + чтение**.
  `-Uninstall` проверяется сценариями `engine-setup.test.sh` (что снимается,
  тома не трогаются, отката нет), README сверяется построчно с параметрами
  скриптов. Путь `-Install` уже прогнан вживую в #6. Живого сноса и чистой ВМ
  нет.

**Ревью диффа, круг 1 (2026-10-13).** Совет по диффу — `council.sh` код 0:
страж, инженер, прагматик `no_objections`; major скептика (лимит скорости
journald при всплеске на загрузке, сброс vhdx при снятии питания) проверяются

Безопасность — approve: задача бэкапа после снятия `-LogonType` только S4U,
без хранимого пароля. Корректность — `changes_requested`: B1 (остатки слов
вне истории решений), B2 (живые пункты приёмки — владелец), M1–M4, N1, N2.

**B1 — способ (а), выбран оркестратором.** Переписаны подсказка
`ops/backup/backup.sh:186` и комментарии двух `.example` (структура та же —

**Решения починки (M4).**
- Отказ `-Install` с кодом 2 по форме `COMPOSE_PROJECT_NAME`
  (`engine-setup.ps1:600–602`) — то же выражение, что `ValidatePattern` у
  `-Project` в `measure-boot.ps1`, в `-Install` — с учётом регистра (строже): без отказа задача замера регистрировалась бы
  с параметром, не проходящим привязку, и падала бы на каждой загрузке молча.
  Сценарий `engine_setup_refuses_bad_project_name`.
- Событие `probe_error` — отказ зонда (дистрибутив есть, docker ещё не active)
  иначе не оставлял бы следа; пишется только при смене текста.
- Сверка `-Distro` в звене «задача замера» (`engine-setup.ps1:917–921`) —
  задача с чужим `-Distro` спрашивала бы не тот движок. Теста на несовпадение
  `-Distro` нет.
- Итог замера называет причину конца опроса и фактическое время
  (`stop=ready|stable|timeout через N мин`) — M1.
- Зонд пропускает неработающие контейнеры (`.State.Running`) — N2.
- В трёх сценариях замера с подменённым `wsl.exe` окно стабильности поднято до
  0.2 мин: 3 с было короче серии опросов через `.cmd`, исход зависел от
  скорости шелла. Утверждения не ослаблены.

**Решения починки круга 2.**
- M1: зонд печатает неработающий контейнер проекта строкой
  `container name=<имя> state=stopped`, без моментов прошлого запуска (смысл
  N2 круга 1 сохранён). `ready` и `ok` требуют running и healthy от каждого
  названного зондом контейнера; итог называет неработающие. Контейнер без

## Отвергнуто

- Сбрасывать `Healthy` контейнера при последующем unhealthy в замере (nit
  ревью круга 3) — критерий требует момент перехода в healthy; устоявшееся
  состояние страхует `/health`, а флаг-откат усложнил бы условие остановки.

- Вариант A развилки HA (без healthcheck, `healthcheck=нет` в журнале
  замера) — критерий выполнялся бы только после его правки в issue; владелец
  выбрал B.
- Решение о healthcheck HA дополнением к 0028 вместо отдельной записи 0029
  (прагматик, круг 3: минус файл, план до порога) — владелец явно выбрал
  отдельную запись, зная о 0027.
- Живой прогон `-Uninstall` и проверка README на чистой ВМ — владелец выбрал
  тесты и чтение: живой снос останавливает рабочий стек, чистой машины нет.

## Шаги

- Воспроизведение пропущено: задача не баг (`chore`).
- Совет по плану: маршрут medium — скептик, инженер, страж. Признаки:
  новая функциональность; глобальный переключатель — драйвер логов на весь
  движок (греп `log-driver`/`logging` по репозиторию: нигде не задан); правка
  обвязки — запись 0028. Прагматик не зван на круги 1–2 (9 и 10 файлов при
  пороге 11), зван на круг 3: 12 файлов после записи 0029 и индекса.
- Реализация одним `step-implement`, последовательно, четырьмя коммитами —
  по карточке плана «параллелить нельзя». Довод не сверялся по `files`: три
  среза не пересекались. Владелец спросил о параллели; правка правил о срезах
  ведётся отдельно (совет по предложению), не в этой задаче.
- Ревью диффа по маршруту high: корректность, безопасность и совет по диффу
  (скептик, инженер, страж, прагматик — размер выше порога). Признаки
  перенесены с плана: новая функциональность, глобальный переключатель,
  правка обвязки (0028, 0029, индекс решений).
