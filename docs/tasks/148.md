## Решения

**Триаж.** `ready`, вопросов владельцу нет; тип `type/chore`, не `decision`;
ссылок на ТЗ нет. Способы проверки по критерию: отказы `validate`, граница
порога и `trivial` со срезами — сценарии `scripts/plan.test.sh`; планы ниже
порога проходят без правки — `plan.sh validate` по `docs/tasks/*.plan.json` и
`scripts/fixtures/plans/*.json`; напоминание хука — проба в
`.claude/hooks/tests/test_rules_map.py`; тексты — чтение и `grep`; план этой
задачи — `plan.sh validate docs/tasks/148.plan.json`. Пункты «Учесть в плане»
(как CANON несёт `slices`, форма пробы для Agent, git и хуки внутри worktree
на Windows) — решения плана, а не вопросы владельцу.

**Доказательство пункта «validate проходит на старых планах без правки».**
Буквально он невыполним до правки: на `origin/main` старые планы и фикстуры
уже красные из-за дрейфа дерева и схемы (131 — 61 нарушение, 4 — 0, фикстура
83 — 18). С `--at` на исходное дерево они тоже красные (131 — 64, фикстура
83 — 16), а фикстуры красные намеренно. Вопрос владельцу 2026-10-13, ответ:
доказывать так — ни одной строки `нарушение: срезы:` и число нарушений не
больше, чем на `origin/main`.

**План.** Поля `slices` и `single_slice_reason` в схеме необязательные,
иначе старые планы падают на форме. Отказ «полная карточка без срезов»
живёт в `plan.sh` и включается константой `SLICES_FROM_ISSUE=148` — порог
потом отвергнут, см. абзац «Отсечка проверки срезов». Тексты
отказов начинаются с `срезы:`. Строка хука `implement-slices` — без
`subagent_note`, с `repeat: true`. `rule-injector` не меняется, потому что
вызовы Agent идут мимо предфильтра. Реализация режется на три независимых
среза: «форма и валидатор», «напоминание», «тексты». План этой задачи
переводится в новую форму после переноса первого среза.

**Хуки в worktree.** `core.hooksPath` задан абсолютным путём в общем
`.git/config`, поэтому в worktree коммит запускает хуки основной копии
(подтверждено `GIT_TRACE` на коммите плана).

**Отдельная копия.** Задача ведётся в worktree
`.claude/worktrees/feat+148-plan-slices` по просьбе владельца: основная копия
занята веткой #147.

**Совет по плану, круг 1.** Блокеров нет (`council.sh` код 0). Принято:
убрать из плана правку абзаца «Ветка» в `.claude/agents/step-implement.md`
(прагматик, major: сверх issue, дефект не доказан, на срезы этой задачи
правка не подействует — определения заморожены на старте сессии);
наблюдение о ветке worktree остаётся строкой раздела «Склейка срезов». Явное
поле `doc` у строки хука (скептик). Старые планы сверяются множествами
текстов нарушений, а не числами (скептик): исчезнувшее нарушение не
маскирует новое — строже ответа владельца и в него укладывается.

**Отсечка проверки срезов — расходится с issue, решение владельца
2026-10-13.** Порог `SLICES_FROM_ISSUE=148` отвергнут: номер задачи — не
время написания плана, и около пятидесяти открытых задач с номерами меньше
148 получили бы планы без проверки. Решено: проверка срезов действует на
любой план, кроме запуска с `--at` (исторический режим — план сверяется с
деревом, для которого писался, правила срезов тогда не было; фикстуры 81, 83,
93 в `plan.test.sh` остаются зелёными). Исключения для #147 нет: владелец
завершает её до мержа этой задачи — порядок мержа #147, затем #148. Пункт
приёмки «старые планы проходят без правки» снят: завершённые планы в
`docs/tasks/` никто не перепроверяет — ни CI, ни `plan.test.sh`.
