## Решения

**Триаж (2026-10-22).** Вердикт step-triage — `ready=false` по одному пункту:
размер. Оценка в issue 6–12 ч, а правило самого issue велит дробить задачу
больше 8 ч. Остальные пункты выполнены: `/state` и `/action` в `main` —
заглушки `NotImplemented` (`src/Domovoy.Api/Endpoints/ApiV1Endpoints.cs`),
опора есть — `IEntityAllowList.Areas`, `IHaClient.GetStatesAsync`,
`HaEntityState.LastUpdated`, единый формат ошибок `ApiErrorResults`.
Расхождения с ТЗ нет (раздел 5, FR-APP-2, FR-HA-4).

**Размер — один PR (владелец, 2026-10-22).** На вопрос «один PR, два PR в
одной задаче или два issue» владелец ответил: один PR целиком. После ответа
задача готова к работе.

**Совет по плану, круг 1.** Блокеров нет; два major скептика приняты:
`as_of` — момент снятия среза, а не обещание свежести (свежесть по сущности —
`last_updated` от HA); добавлен тест кэш-пути `/state` при подключённом
WebSocket. Nit скептика про формы `value` принят (`50`, `50.0`, `"50"` —
ок, `1e2` — 400). Nit прагматика принят: тест README разбирает фиксированную
форму двух блоков curl, без общего парсера.

**План согласован владельцем (2026-10-22):** «приступай».

**Совет по плану, круг 2.** Блокеров и major нет, план не менялся. Nit
прагматика — убрать тест README и тест кэш-пути — не взяты: первый держит
критерий «вызываются примерами curl из README» в CI, а не только на стенде;
второй — ответ на major скептика круга 1, снять его значит откатить круг.
Nit скептика — на стенде `GET /state` сразу после `POST /action` может
отдать кэш до события — учесть в живой проверке: повтор запроса, не дефект.

**Срез `auth-tests-retarget`.** Отзыв токена (`RevokedTokenIsRejectedOnNextRequest`,
`DeviceTokenLoggingTests`) проверяется на `/api/v1/notifications`, «до» и
«после» — на одном маршруте; контракт среза этот третий случай явно не
называл. Проверки «без токена или с неизвестным — 401» остались на `/state`.

**Базовый снимок движка (до стенда, 2026-10-22).** Контейнеры:
`domovoy-api-1`, `domovoy-postgres-1`, `domovoy-homeassistant-1`. Висящих
томов нет. Образы: `domovoy-migrate:sha-6e34f3f…`, `domovoy-api:sha-6e34f3f…`
(ghcr), `domovoy-api:latest`, `home-assistant:2026.10.1`, `postgres:16-alpine`.

**Срез `endpoints` — расхождения с планом.**
- Формы `value` (`50`, `50.0`, `"50"`) — отдельный Theory
  `ActionAcceptsValueForms`: Fact и Theory под одним именем xUnit не
  совмещает; `ActionCallsServiceForAllowedEntity` остался Fact на `turn_on`.
- Тело ошибки — `{ error: { code, message, details: null } }`, а не ровно
  `{ code, message }`: так пишет общий `ApiErrorResults.Result`, README уже
  описывает формат с `details`. Общий писатель в задаче не правится.
- JSON `null` в `value` — то же, что поле не передано.
- Пустой `ToolResult.Error` — сообщение «Действие не выполнено.»
  (`ApiError.Message` обязателен).
- `ReadAction = "read"` — своя константа в `HomeEndpoints`:
  `HaDomainCatalog.ReadAction` internal в слое Ha.
- В README-примере `/action` есть `Content-Type: application/json`: без
  него curl с `-d` шлёт форму и получает 400. Тест README берёт заголовок
  из самой команды.
- Случаев в Theory больше плана: пустой и `null` код отказа (500),
  пустое тело, `[]`, нестроковый `entity_id`, массив в `value`,
  `text/plain`.

**Ревью диффа, круг 1.** Уровень по диффу high — как по плану; размер выше
порога (1585 > 1538). `guard-lite` чист, `plan.sh drift` — расхождений нет.
Совет по диффу (признаки с плана: контракт API, новая функциональность):
блокеров нет, принятых замечаний нет. Безопасность — approve. Корректность:
blocker — нет живой проверки на стенде (исполняется); major — устаревшая
шапка журнала (исправлена); nit — пустое `ToolResult.Error` без теста
(добавлен `ActionFillsEmptyRefusalMessage`, 367 тестов).

**Сеть движка — в этом PR (владелец, 2026-10-22).** Живая проверка упала на
`dotnet restore` в сборке api: NU1301. Разбор: весь трафик хоста идёт через
туннель WireGuard с MTU 1420, у движка eth0 — 1500; TLS к `api.nuget.org`
виснет после Server hello. Проба: контейнер с MTU 1500 — тайм-аут, тот же
контейнер после `ip link set eth0 mtu 1380` — 200. Юнит
`domovoy-mss-clamp` (`deploy/windows/provision-engine.sh`, `ensure_mss_clamp`)
активен, но `--clamp-mss-to-pmtu` берёт MTU eth0 движка (1500 → MSS 1460):
узкое место за NAT WSL ему не видно. Владелец выбрал фиксированный MSS в том
же юните и в этом же PR.

**Совет по плану, круг 3 (срез `engine-mss`).** Блокеров нет. Два major —
прагматик (снятие прежнего правила — лишнее) и скептик (снятие до `restart`
при сбое `restart` оставит движок без клампа) — закрыты одной правкой:
цикл `iptables -D` и его тест убраны. Прежнее правило безвредно: TCPMSS
меньший MSS не поднимает, оба правила дают 1340, при перезапуске
дистрибутива оно исчезает. Nit прагматика про тест README не взят — решено
в круге 2. Потолок кругов совета исчерпан: план — человеку. Владелец
согласовал (2026-10-22): «продолжай».

**Срез `engine-mss` — расхождения с планом.** Правило собирается строкой
`"… --set-mss $mss"`, текст юнита байт в байт по контракту. Тест строже
плана: подменённый `iptables` пишет в общий с `systemctl` лог, точная
последовательность доказывает, что функция его не зовёт; повтор сверяется
строкой `enable|start`. Три коммита вместо двух: пересборку через
`git reset --soft` отбил классификатор авто-режима, поправки легли
отдельным коммитом. Хуки коммита в worktree среза шли из основной копии
(`core.hooksPath` абсолютный) — gitleaks прогнан по диапазону после переноса.

**Ревью диффа, круг 2 — последний.** Уровень high, `guard-lite` чист,
`drift` пуст. Безопасность — approve. Совет: страж и инженер без замечаний;
прагматик — major «вынести engine-mss отдельным PR» (снимается решением
владельца «в этом же PR», о чём пишет сам прагматик); скептик — два major о
непройденной живой проверке (один отброшен `council.sh` по якорю вне диффа,
`council.sh` — код 1, по существу совпадает с blocker корректности).
Корректность — blocker: живые части A-state, A-action, A-readme,
A-engine-mss не получены; кода не требует. Круги ревью и общий предел
исчерпаны с оставшимся blocker — триггер, решает владелец.

**Blocker ревью круга 2 снят живой проверкой.** Правку кода он не требовал;
живые части A-state, A-action, A-readme, A-engine-mss получены (таблица
«Проверено»). Миграцию в базу стенда агент применил с разрешения владельца:
`stand.sh` миграций не применяет — уходит в «Попутно» PR.

## Отвергнуто

- `mtu` в `/etc/docker/daemon.json` — покрывает только мост по умолчанию,
  сети compose стенда и боевого стека остаются 1500; нужен перезапуск dockerd.
- `networkingMode=mirrored` в `.wslconfig`, MSS clamp на стороне WireGuard —
  правка вне репозитория, на стороне владельца.
- Разовое `ip link set eth0 mtu 1380` в движке — до перезапуска WSL;
  следующий стенд упал бы так же.

- Поле `requires_confirmation` в сущности `/state` (nit инженера) —
  подтверждение — признак действия, а не сущности; поле из одного дескриптора
  могло бы соврать. Взамен — строка в README про 409 до #47.
- `as_of` = время последнего кадра WebSocket — меряет живость, а не свежесть,
  и требует правки `src/Domovoy.Ha/**`.

- Разбиение на два PR или два issue — владелец выбрал один PR.
