## Решения

**Триаж (2026-10-22).** Вердикт step-triage — `ready=false` по одному пункту:
размер. Оценка в issue 6–12 ч, а правило самого issue велит дробить задачу
больше 8 ч. Остальные пункты выполнены: `/state` и `/action` в `main` —

Расхождения с ТЗ нет (раздел 5, FR-APP-2, FR-HA-4).

**Размер — один PR (владелец, 2026-10-22).** На вопрос «один PR, два PR в
одной задаче или два issue» владелец ответил: один PR целиком. После ответа
задача готова к работе.

**Совет по плану, круг 1.** Блокеров нет; два major скептика приняты:
`as_of` — момент снятия среза, а не обещание свежести (свежесть по сущности —
`last_updated` от HA); добавлен тест кэш-пути `/state` при подключённом
WebSocket. Nit скептика про формы `value` принят (`50`, `50.0`, `"50"` —
ок, `1e2` — 400). Nit прагматика принят: тест README разбирает фиксированную
форму двух блоков curl, без общего парсера.

**План согласован владельцем (2026-10-22):** «приступай».

**Совет по плану, круг 2.** Блокеров и major нет, план не менялся. Nit
прагматика — убрать тест README и тест кэш-пути — не взяты: первый держит
критерий «вызываются примерами curl из README» в CI, а не только на стенде;
второй — ответ на major скептика круга 1, снять его значит откатить круг.
Nit скептика — на стенде `GET /state` сразу после `POST /action` может
отдать кэш до события — учесть в живой проверке: повтор запроса, не дефект.

**Срез `auth-tests-retarget`.** Отзыв токена (`RevokedTokenIsRejectedOnNextRequest`,
`DeviceTokenLoggingTests`) проверяется на `/api/v1/notifications`, «до» и
«после» — на одном маршруте; контракт среза этот третий случай явно не
называл. Проверки «без токена или с неизвестным — 401» остались на `/state`.

**Базовый снимок движка (до стенда, 2026-10-22).** Контейнеры:
`domovoy-api-1`, `domovoy-postgres-1`, `domovoy-homeassistant-1`. Висящих
томов нет. Образы: `domovoy-migrate:sha-6e34f3f…`, `domovoy-api:sha-6e34f3f…`
(ghcr), `domovoy-api:latest`, `home-assistant:2026.10.1`, `postgres:16-alpine`.

**Срез `endpoints` — расхождения с планом.**
- Формы `value` (`50`, `50.0`, `"50"`) — отдельный Theory
  `ActionAcceptsValueForms`: Fact и Theory под одним именем xUnit не
  совмещает; `ActionCallsServiceForAllowedEntity` остался Fact на `turn_on`.
- Тело ошибки — `{ error: { code, message, details: null } }`, а не ровно
  `{ code, message }`: так пишет общий `ApiErrorResults.Result`, README уже
  описывает формат с `details`. Общий писатель в задаче не правится.
- JSON `null` в `value` — то же, что поле не передано.
- Пустой `ToolResult.Error` — сообщение «Действие не выполнено.»
  (`ApiError.Message` обязателен).
- `ReadAction = "read"` — своя константа в `HomeEndpoints`:
  `HaDomainCatalog.ReadAction` internal в слое Ha.
- В README-примере `/action` есть `Content-Type: application/json`: без
  него curl с `-d` шлёт форму и получает 400. Тест README берёт заголовок
  из самой команды.
- Случаев в Theory больше плана: пустой и `null` код отказа (500),
  пустое тело, `[]`, нестроковый `entity_id`, массив в `value`,
  `text/plain`.

## Отвергнуто

- Поле `requires_confirmation` в сущности `/state` (nit инженера) —
  подтверждение — признак действия, а не сущности; поле из одного дескриптора
  могло бы соврать. Взамен — строка в README про 409 до #47.
- `as_of` = время последнего кадра WebSocket — меряет живость, а не свежесть,
  и требует правки `src/Domovoy.Ha/**`.

- Разбиение на два PR или два issue — владелец выбрал один PR.
