## Решения

**Триаж.** `ready: false` по одному пункту `docs/rules/triage.md` — объём:
по перечню файлов задачи 12 файлов при пороге `size.files` = 11 в
`scripts/risk.json`. Пути из задачи существуют, у каждого пункта критерия
назван способ проверки. Воспроизведение второго дефекта — на самой #152 без
комментариев: `gh issue view 152 --comments` даёт пустой вывод, форма
`--json` даёт тело. Задача трогает обвязку контроля (`harness_control`) —
уровень high заявлен в теле задачи.

**Один PR, без разбиения.** Вопрос триажа владельцу, ответ 2026-10-13: «Один
PR». Обе части — короткие правки обвязки, уровень high и так задан хуками;
разбиение дало бы второй полный маршрут high.

**Третья часть — ветка задачи в worktree.** Владелец 2026-10-13, после того
как оркестратор переключил основное дерево с ветки #151 на ветку #152: «надо
видимо добавить правило, что нужно проверить основной репо, вдруг там ведется
работа» и «скорректировать правило создание ветки». Принято: ветка задачи
ведётся в `.claude/worktrees/<N>`, основное дерево не переключается; проверка
«чист ли основной репо» вместо этого не годится — чистый `git status` не
доказывает, что там не работает параллельная сессия.

**Совет, круг 1 — исправление плана.** Блокеров нет, majors приняты:
сессия оркестратора входит в worktree задачи (`EnterWorktree` с `path`) до
запуска шагов — тогда cwd шагов и советников — worktree, это подтвердили шаг
плана и совет на этой задаче; уборка после мерджа — выйти из worktree, удалить
его из основного дерева, затем ветки; занятая ветка (`git worktree add`
отказывает с `already used by worktree`) — стоп и вопрос человеку; пробы
`merge-wait` на цепочках; команды уборки — в тест прав. Замечание прагматика
о хуке под `git worktree add` принято частично: regex не расширяется, меняется
только note `one-task-one-branch`. Замечание скептика о пустом `issue.md`
отброшено: файл 7172 байта, скептик его не читал (нет в `read`).

**Ожидание мерджа — скрипт, а не однострочник.** Замер оркестратора
2026-10-13: в сессии, изолированной в worktree, Bash отказывает однострочному
циклу ожидания («this command is too complex to verify that it stays inside
the worktree»); тот же цикл из файла на #150 вывел `MERGED`, на несуществующем
PR вышел с кодом 1 и диагностикой. Отсюда `scripts/merge-wait.sh` с тестом и
шагом CI — файлов 15.
