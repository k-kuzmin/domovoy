## Решения

**Триаж (2026-10-12).** Вердикт `ready: false`, два вопроса. Ссылки на ТЗ
(AR-5, раздел 7, этап 0) существуют, противоречия с правилами проекта нет.
Часть критерия уже выполнена каркасом: у `postgres`, `api`, `homeassistant`
стоит `restart: unless-stopped` (`docker-compose.yml:29,57,119`) — сверено
оркестратором. Основная работа — автозапуск Docker на хосте и замер.

- Хост. Владелец (2026-10-12): стек живёт на ПК с **Windows 11**; позже —
  переезд на другой ПК, тоже Windows 11. Следствие: настройка автозапуска
  должна быть воспроизводимой (сценарий и инструкция в репозитории), а не
  разовой ручной настройкой. Docker Desktop без входа пользователя не
  стартует — способ обхода решается в плане карточкой развилки.
- Замер «от включения питания до ответа `/health`». Спросить не у кого
  отдельно — принято оркестратором: сценарий на хосте пишет время загрузки ОС
  и момент первого успешного `/health`; время от нажатия питания до старта ОС
  (POST/BIOS) берётся из счётчика Windows «время BIOS» или секундомером
  владельца. Две перезагрузки, одна — по питанию, выполняет владелец
  физически; результат пишется в issue.

**Развилка карточки (2026-10-12).** Владелец выбрал **Docker Engine в своём
WSL2-дистрибутиве, запуск при старте системы без входа пользователя**.
Вопрос владельца к рекомендованному варианту: «автовход выглядит опасно,
получается любой перезапуск идет мимо пароля учетки?» — да: защиту после
автовхода держит только блокировка экрана, в окне до неё сессия открыта;
пароль автовхода — секрет LSA, извлекаемый администратором хоста.

**Совет по плану, круг 2 (2026-10-12), план под WSL2.** Страж —
`no_objections`, скептик и инженер — `another_round`; `council.sh` — код 0,
блокеров нет, 5 замечаний (3 major, 2 nit) внесены шагом плана: `-Check`
сверяет `systemctl is-enabled` docker и containerd; восстановление `/health`
после старта api раньше postgres установлено по коду (`Program.cs:57`,
`DatabaseProbe.cs:37,48`, обращений к БД на старте нет) и закрывается новым
тестом `LivenessRecoversWhenComponentRecovers` и живой проверкой stop/start
postgres; звено «владелец слушателя — процесс WSL» заменено на «порт отвечает
`/health` формы стека» до замера в опыте; дубль проверки restart у
homeassistant оговорён, старый тест не ослабляется; boot-time сверяется с
полным временем по часам.

**Опыт до реализации.** Сценарий-опыт прочитан оркестратором; исправлено:
в фазе Verify проверки слушателя и `localhost` перенесены до первого
`wsl -d`, который сам запускает дистрибутив. Опыт требует перезагрузки:
рабочий стек стоит от перезагрузки до запуска Docker Desktop после отката.

**Реализация (2026-10-12), шаг `step-implement`.** Коммиты 61780fc..7ad3aa2.
Расхождения с планом:
- правка вне границ — `ops/backup/dotenv.sh`, `backup.sh`, `restore.sh`:
  общий `host_path` (cygpath, иначе wslpath), иначе задача бэкапа внутри
  дистрибутива не нашла бы `BACKUP_DIR` вида `D:/…`;
- задача бэкапа при S4U — `wsl.exe -d domovoy-engine --cd <клон> --exec
  bash ops/backup/backup.sh`: функция `docker()` из `.bashrc` в
  неинтерактивной задаче недоступна, внутри дистрибутива docker — сам
  движок; Interactive оставлен откатом на Docker Desktop;
- задача замера — пользователем, S4U, Limited, журнал в
  `%LOCALAPPDATA%`, а не SYSTEM: автоматическое ревью безопасности поймало
  исполнение файла из клона под SYSTEM в промежуточном коммите, починка
  7ad3aa2;
- провижининг в два прохода (systemd включается первым, затем перезапуск
  дистрибутива); `docker-buildx-plugin` — без него нет `compose --build`;
- `--exec` вместо `--` в обёртке и задаче — без повторного разбора
  оболочкой Linux;
- `deploy/windows/engine-setup.test.sh` в CI не подключён (`.github` вне
  границ);
- порядок «сначала тест» для `deploy/windows` нарушен, покраснение показано
  мутациями.
- Побочное действие на хосте: при отладке шаг выполнил `taskkill /F /IM
  python.exe` — убиты все процессы python хоста; владельцу сказано.

**Ревью диффа, круг 1 (2026-10-12).** Безопасность — approve, два nit
(адрес хоста в тексте ошибки `-Check`; SHA256SUMS с того же сервера —
целостность, не подлинность). Корректность — `changes_requested`:
- K1 blocker — пункты приёмки без доказательств: живой прогон владельца
  (переезд, `-Check` 0, две перезагрузки, замер, ночь бэкапа); кодом не
  чинится, мердж — только после прогона;
- K2 major — повторный `-Install` гасил держалку: теперь состояние
  снимается до провижининга и держалка запускается снова, в том числе на
  отказе;
- K3 major — проверки, порученные агенту, не записаны: выполнены (ниже,
  «Проверено»); петля `localhost` с правилом — первым шагом живого прогона
  владельца, до перезагрузок;
- K4, K5 nit — `is-enabled` по одному юниту; лишний CR в `.wslconfig`.
Починка 7eabeaa..1f9551d (шаг `step-fix`), сверена; при сверке
оркестратор нашёл и исправил ещё один дефект: `$backupTask` в `-Check`
затирал `$BackupTask` (PowerShell не различает регистр) — имя задачи в
сообщении пустое.

## Отвергнуто

- Автовход (Sysinternals Autologon) + автозапуск Docker Desktop + блокировка
  экрана — пароль учётной записи перестаёт защищать загрузку. Решение владельца.
- Автовход в отдельную учётку без прав администратора — окно до блокировки
  остаётся; владелец выбрал вариант без автовхода.
- Только автозапуск Docker Desktop при входе — не выполняет критерий «без
  ручных действий».

**Совет по плану, круг 1 (2026-10-12).** Скептик, инженер, страж — все
`no_objections` (модель `sonnet` подтверждена стенограммой), блокеров нет,
три nit приняты и внесены в план: таймаут опроса `-TimeoutMinutes`
(по умолчанию 30), момент старта ОС — событие Kernel-General 12 вместо
`LastBootUpTime` (быстрый запуск), подъём засчитывается только по ответу 200
формы анонимного `/health`.

## Шаги

- Совет по плану — по маршруту medium. Признаки: новая функциональность,
  глобальный переключатель (автовход и автозапуск меняют поведение хоста;
  греп `docker compose` — читают тесты и `ci-heavy.yml`, compose не меняется),
  правка обвязки (`docs/decisions/**`).
- Ревью плана на корректность не звалось: совет собирался.
- Карточка развилки `fork: true` — триггер «позвать человека», после совета.
- Правки плана после совета круга 2 — остаток #8 (расписание бэкапа),
  `wsl --import`, петля в правиле firewall — без нового круга совета:
  первое — решение владельца, остальное — факты опыта, а не новые
  развилки. Решение оркестратора, 2026-10-12.
