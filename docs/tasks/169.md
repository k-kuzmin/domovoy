**Ответы владельца (2026-10-19).** Пункт 4 входит в #169 — план дописывает
критерий и сценарий `scripts/stand.test.sh` на каждую из трёх подпроблем.

**Совет по плану, круг 1.** `council.sh` — код 0, блокеров нет; три major,
шесть nit. Исправлено шагом плана:
- родителя `~/domovoy-stand` может не быть (инженер, скептик) — захват
  `mkdir -p` родителя, затем `mkdir` каталога и метка одним вызовом, исходы
  `claimed`/`taken`/`error` с разными отказами, два сценария;
- повтор `up` того же `N` (скептик) — отклонён по существу: повторного `up`
  без `down` нет ни в правилах, ни в сценариях (`implement.md:147`,
  `implement.md:163` требует `down` в том же ходе работы); принята вторая
  половина — после захвата каждый выход идёт через `fail_up`. Решение за
  владельцем при просмотре плана;
- исключённые диапазоны портов Windows (скептик, nit) — принято как дефект:
  на машине владельца исключён порт внутри 20000…29999; `port_busy` читает
  `netsh.exe … excludedportrange`;
- `probe` не резервирует порт (инженер) — порядок «запуск сразу после probe»;
- `pull --ff-only` — принятый риск с условиями вместо довода о «читающей
  сессии»;
- подкоманда `probe` сверх нужного (прагматик) — отклонено: один источник
  метки для `down` и проверка занятых портов правилом не делаются;
- хрупкие якоря текста в `test_rules_map.py` (прагматик) — убраны, проверка
  текста — `grep -nF` в контракте приёмки.

Второй круг совета не собирался: блокеров нет
